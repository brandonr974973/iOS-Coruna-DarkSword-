## 1. 执行摘要

iOS 的防暴力破解体系是移动安全领域最精密的多层防御系统之一。它不依赖单一机制，而是通过**硬件速率限制、渐进式延迟、自动擦除、USB 限制、位置感知延迟、锁定模式**等多重防线构成纵深防御体系。即使攻击者拥有设备的物理访问权限，这些机制协同工作也能将暴力破解的成功率压缩到接近零。

本报告完整解析 iOS 防暴力破解的每一层防御机制，从 Secure Enclave 的硬件级速率限制到失窃设备保护的 1 小时延迟，从密码学密钥派生链到取证工具的对抗博弈，提供安全研究者和高级用户所需的深度技术理解。

**核心发现：**

- Secure Enclave 的硬件速率限制是不可绕过的第一道防线——即使越狱也无法解除
- 6 次失败后设备进入递增延迟锁定，从 1 分钟到 1 小时
- 10 次失败后可触发自动擦除，销毁所有加密密钥
- USB 限制模式在锁定 1 小时后关闭数据端口，阻止 GrayKey 等取证工具
- 失窃设备保护在不熟悉位置增加额外 1 小时延迟，对抗胁迫解锁
- 20+ 位随机密码在物理攻击下实际不可破解

### 1.1 防御层次全景

```
┌─────────────────────────────────────────────────────────────────┐
│              iOS 防暴力破解纵深防御体系                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Layer 7: 紧急锁定 ← 5 次点击，立即禁用生物识别                  │

│  Layer 2: 渐进式延迟 ← 1 分钟 → 5 → 15 → 1 小时               │

└─────────────────────────────────────────────────────────────────┘
```

## 3. 密码学基础：为什么密码是信任根

### 3.1 密码在 iOS 安全中的核心地位

iOS 的所有数据保护都建立在用户密码之上。密码不仅用于解锁设备，更是整个加密体系的根密钥。

```
密码 → 信任根

用户密码
    │
    ▼ PBKDF2 ( iterations + salt )
    │
密码派生密钥 (Password-derived Key)
    │
    ▼ 与 UID 密钥结合
    │
类密钥 (Class Key)
    │
    ├── 完整保护类密钥
    ├── 除非打开类密钥
    ├── 首次解锁后类密钥
    └── 无保护类密钥
    │
    ▼
文件密钥 (Per-file Key)
    │
    ▼ AES-256
    │
加密数据
```

### 3.2 密钥派生链

```
密钥派生详细流程：

1. 用户输入密码
   → 密码通过键盘输入
   → 安全传输到 Secure Enclave

2. PBKDF2 密钥派生
   → 算法：PBKDF2-HMAC-SHA256
   → 迭代次数：~80,000 次（iOS 16+，持续增加）
   → Salt：随机生成，存储在 Secure Enclave
   → 输出：256 位密码派生密钥

3. UID 绑定
   → 密码派生密钥与 UID 密钥结合
   → UID 密钥在芯片制造时写入
   → UID 不可导出、不可读取
   → 即使 Apple 也无法获取 UID

4. 类密钥生成
   → 使用 HKDF 从结合密钥派生类密钥
   → 每个保护类别一个类密钥
   → 类密钥用于加密文件密钥

5. 文件加密
   → 每个文件使用唯一的文件密钥
   → 文件密钥由类密钥加密
   → 加密数据存储在闪存中

安全属性：
→ 没有密码 = 没有类密钥 = 无法解密文件
→ 没有 UID = 即使有密码也无法在其他设备解密
→ 擦除 UID = 所有数据永久不可恢复
```

### 3.3 UID 密钥的不可提取性

| 属性 | 说明 |
|------|------|
| 存储位置 | Secure Enclave 内的一次性可编程（OTP）熔丝 |
| 写入时机 | 芯片制造时随机生成并写入 |
| 可读性 | 不可读取——硬件设计禁止 |
| 可导出性 | 不可导出——无硬件接口 |
| 唯一性 | 每个芯片唯一——出厂后不可更改 |
| Apple 访问 | Apple 也无法获取——不存储在 Apple 服务器 |

**关键安全意义：** 即使攻击者能物理提取闪存数据并拥有无限计算资源，没有 UID 密钥就无法完成密钥派生——这使得离线暴力破解在密码学上不可行（除非能攻破 Secure Enclave）。

## 4. 第一层防线：Secure Enclave 硬件速率限制

### 4.1 硬件速率限制机制

Secure Enclave 在硬件层面实施密码尝试的速率限制。这是防暴力破解的第一道也是最关键的防线。

```
密码验证流程（硬件速率限制）：

用户输入密码
    │
    ▼
┌─────────────────────────────┐
│      Secure Enclave          │
│                              │
│  1. 接收密码                 │
│  2. 检查尝试计数器           │
│     → 计数器 > 阈值？        │
│     → 是：返回延迟            │
│     → 否：继续验证            │
│  3. 执行密钥派生             │
│  4. 比较密钥                 │
│  5. 成功：重置计数器          │
│     失败：递增计数器          │
│  6. 返回结果                 │
│                              │
└─────────────────────────────┘
```

### 4.2 速率限制参数

| 失败次数 | 延迟时间 | 累计等待 | 说明 |
|----------|----------|----------|------|
| 1-5 | 无延迟 | 0 | 正常尝试 |
| 6 | 1 分钟 | 1 分钟 | 首次延迟 |
| 7 | 5 分钟 | 6 分钟 | 递增延迟 |
| 8 | 15 分钟 | 21 分钟 | 显著延迟 |
| 9 | 1 小时 | 81 分钟 | 长延迟 |
| 10 | 1 小时 | 141 分钟 | 长延迟（如启用擦除则触发） |

**关键安全属性：**
- 延迟由 Secure Enclave **硬件**强制执行，软件无法绕过
- 即使越狱也无法修改延迟——因为逻辑在独立处理器中
- 延迟期间无法通过任何方式加速
- 重启设备不会重置计数器
- 只有成功输入密码才能重置计数器

### 4.3 为什么硬件速率限制不可绕过

```
绕过尝试分析：

尝试 1：软件修改
→ 修改 iOS 系统代码
→ 结果：无效——延迟逻辑在 Secure Enclave 固件中
→ Secure Enclave 固件独立于 iOS，由 Secure Boot 保护

尝试 2：越狱绕过
→ 越狱获取 root 权限
→ 结果：无效——Secure Enclave 是独立处理器
→ 越狱仅影响主处理器，不影响 Secure Enclave

尝试 3：直接访问 Secure Enclave
→ 物理探测 Secure Enclave 芯片
→ 结果：无效——Secure Enclave 有独立内存保护
→ 外部接口仅暴露加密通信

尝试 4：替换 Secure Enclave
→ 用修改过的芯片替换
→ 结果：无效——Secure Boot 验证芯片身份
→ 替换后设备无法启动

尝试 5：侧信道提取
→ 功耗分析提取密码
→ 结果：极其困难——需要专业设备
→ Secure Enclave 有噪声注入缓解

结论：硬件速率限制在当前技术下不可绕过
```

### 4.4 速率限制的攻击影响

```
在线暴力破解可行性分析：

4 位数字密码（10,000 种组合）：
→ 前 5 次：无延迟（5 次尝试）
→ 第 6 次：等待 1 分钟
→ 第 7 次：等待 5 分钟
→ 第 8 次：等待 15 分钟
→ 第 9 次：等待 1 小时
→ 第 10 次：触发擦除（如启用）
→ 实际可尝试：最多 9 次（无擦除）或 10 次（有擦除）
→ 破解概率：9/10,000 = 0.09%
→ 结论：不可行

6 位数字密码（1,000,000 种组合）：
→ 实际可尝试：最多 9 次
→ 破解概率：9/1,000,000 = 0.0009%
→ 结论：完全不可行

字母数字密码：
→ 组合空间 > 10^20
→ 可尝试：最多 9 次
→ 破解概率：≈ 0
→ 结论：密码学不可破解
```

## 5. 第二层防线：渐进式延迟锁定

### 5.1 延迟锁定机制

当密码尝试失败次数达到阈值时，iOS 进入延迟锁定状态：

```
延迟锁定状态机：

┌──────────┐     失败 6 次     ┌──────────────┐
│  正常    │ ──────────────→  │  1 分钟延迟  │
│  状态    │                   │  锁定        │
└──────────┘                   └──────┬───────┘
     ▲                                │
     │ 成功输入                        │ 等待 1 分钟
     │                                ▼
     │                         ┌──────────────┐
     └──────────────────────── │  5 分钟延迟  │
                               │  锁定        │
                               └──────┬───────┘
                                      │ 等待 5 分钟
                                      ▼
                               ┌──────────────┐
                               │  15 分钟延迟 │
                               │  锁定        │
                               └──────┬───────┘
                                      │ 等待 15 分钟
                                      ▼
                               ┌──────────────┐
                               │  1 小时延迟  │
                               │  锁定        │
                               └──────┬───────┘
                                      │ 等待 1 小时
                                      ▼
                               ┌──────────────┐
                               │  持续锁定    │
                               │  (需连接电脑) │
                               └──────────────┘
```

### 5.2 锁定界面状态

| 状态 | 显示信息 | 可执行操作 | 退出方式 |
|------|----------|------------|----------|
| 正常 | 输入密码提示 | 输入密码/使用生物识别 | 成功输入 |
| 1 分钟延迟 | "iPhone 不可用，请 1 分钟后重试" | 等待 | 等待结束或连接电脑 |
| 5 分钟延迟 | "iPhone 不可用，请 5 分钟后重试" | 等待 | 等待结束或连接电脑 |
| 15 分钟延迟 | "iPhone 不可用，请 15 分钟后重试" | 等待 | 等待结束或连接电脑 |
| 1 小时延迟 | "iPhone 不可用，请 1 小时后重试" | 等待 | 等待结束或连接电脑 |
| 安全锁定 | "iPhone 不可用，请连接电脑" | 连接电脑恢复 | 使用电脑恢复 |

### 5.3 延迟期间的设备行为

```
延迟锁定期间的系统行为：

1. 界面锁定
   → 密码输入框禁用
   → 显示倒计时
   → 生物识别禁用

2. 通知处理
   → 来电仍可接听（滑动接听）
   → 通知显示（取决于锁屏设置）
   → 紧急 SOS 可用

3. 后台活动
   → 系统继续运行
   → 后台应用继续执行
   → 网络活动继续
   → 闹钟继续工作

4. 计数器行为
   → 失败计数器保持
   → 不因重启重置
   → 不因等待重置（仅成功输入重置）

5. 数据保护
   → 完整保护类数据不可访问
   → 除非打开类数据可继续写入
   → 首次解锁后类数据保持可访问
```

### 5.4 延迟锁定的安全意义

| 攻击场景 | 无延迟 | 有延迟 | 安全增益 |
|----------|--------|--------|----------|
| 快速暴力破解（机器） | 每秒 1000 次 | 每小时 4 次 | 250x 减速 |
| 手动尝试（人工） | 每分钟 10 次 | 每小时 4 次 | 2.5x 减速 |
| 4 位密码破解 | < 3 秒 | > 40 小时 | 不可行 |
| 6 位密码破解 | < 5 分钟 | > 277 天 | 不可行 |

## 6. 第三层防线：自动擦除机制

### 6.1 自动擦除机制

iOS 提供在 10 次密码失败后自动擦除设备的选项：

```
自动擦除配置：

设置 → 面容 ID 与密码 → 抹掉数据 → 开启

效果：
→ 第 10 次密码失败后
→ 设备自动开始擦除
→ 所有数据被删除
→ 加密密钥被销毁
→ 设备恢复出厂设置
```

### 6.2 擦除过程

```
自动擦除技术流程：

1. 触发条件
   → 第 10 次密码验证失败
   → Secure Enclave 确认计数器达到阈值

2. 擦除启动
   → Secure Enclave 触发擦除流程
   → 向主处理器发送擦除指令

3. 密钥销毁
   → 销毁所有类密钥（Class Keys）
   → 销毁密码派生密钥
   → 销毁 UID 密钥的缓存副本
   → 注意：UID 本身不可销毁（熔丝），但密钥派生链断裂

4. 数据删除
   → 删除文件系统元数据
   → 标记所有数据块为可用
   → 由于密钥已销毁，数据不可恢复

5. 系统重置
   → 恢复出厂设置
   → 删除所有用户数据
   → 保留激活锁（需要 Apple ID）

6. 完成
   → 设备变为"新设备"状态
   → 需要 Apple ID 激活（激活锁）
   → 所有用户数据永久丢失
```

### 6.3 擦除的密码学保证

```
为什么擦除后数据不可恢复：

加密数据 + 销毁密钥 = 密码学不可恢复

闪存芯片上的数据：
┌─────────────────────────────────┐
│  [加密数据] [加密数据] [加密数据] │
│  [加密数据] [加密数据] [加密数据] │
│  [加密数据] [加密数据] [加密数据] │
│  ...                             │
└─────────────────────────────────┘

解密密钥（已销毁）：
┌─────────────────────────────────┐
│  [UID 密钥] → 已销毁            │
│  [密码密钥] → 已销毁            │
│  [类密钥]   → 已销毁            │
│  [文件密钥] → 已销毁（加密存储） │
└─────────────────────────────────┘

结果：
→ 闪存数据仍在（可物理读取）
→ 但无法解密（密钥已销毁）
→ 等效于安全擦除（密码学意义）
→ 即使物理提取闪存也无法恢复
```

### 6.4 自动擦除的风险与收益

| 维度 | 收益 | 风险 |
|------|------|------|
| 数据安全 | 防止数据泄露 | 意外触发导致数据丢失 |
| 隐私保护 | 保护敏感信息 | 无法恢复重要数据 |
| 反取证 | 阻止执法提取 | 可能销毁合法证据 |
| 设备保护 | 防止未授权访问 | 需要重新设置设备 |

**推荐：** 高安全需求用户启用自动擦除。普通用户谨慎——意外触发可能导致数据丢失。

## 7. 第四层防线：USB 限制模式

### 7.1 USB 限制模式

iOS 11.4.1+ 引入 USB 限制模式，在设备锁定一段时间后关闭 USB 数据端口的数据传输功能：

```

├── 支持数据传输

设备锁定 > 1 小时：
├── USB 端口仅支持充电
├── 数据传输被禁用
├── 配件连接被拒绝
├── iTunes/Finder 无法连接
└── 取证工具无法连接
```

```
│                                          │
```

## 8. 第五层防线：失窃设备保护（1 小时延迟）

### 8.1 失窃设备保护概述

iOS 17.3+ 引入失窃设备保护（Stolen Device Protection），在"不熟悉的位置"对敏感操作增加 1 小时安全延迟：

```
失窃设备保护触发条件：

设备位置 → 是否熟悉位置？
    │
    ├─ 是（家、办公室等）
    │   → 正常安全流程
    │   → 生物识别即可
    │
    └─ 否（陌生位置）
        → 失窃设备保护激活
        → 敏感操作需要：
           1. 生物识别验证
           2. 等待 1 小时
           3. 再次生物识别验证
```

### 8.2 受保护的操作

| 操作 | 正常模式 | 失窃设备保护（熟悉位置） | 失窃设备保护（陌生位置） |
|------|----------|------------------------|------------------------|
| 解锁设备 | Face ID | Face ID | Face ID |
| 自动填充密码 | Face ID | Face ID | Face ID |
| 更改 Apple ID 密码 | Face ID | Face ID | Face ID + 1h 延迟 |
| 关闭"查找我的" | Face ID | Face ID | Face ID + 1h 延迟 |
| 重置设备 | Face ID | Face ID | Face ID + 1h 延迟 |
| 查看密码自动填充 | Face ID | Face ID | Face ID + 1h 延迟 |
| 使用密码自动填充 | Face ID | Face ID | Face ID + 1h 延迟 |
| 关闭失窃设备保护 | Face ID | Face ID | Face ID + 1h 延迟 |

### 8.3 1 小时延迟的安全意义

```
胁迫场景分析：

攻击者窃取设备 + 胁迫用户解锁：

无失窃设备保护：
1. 攻击者获取设备
2. 胁迫用户用 Face ID 解锁
3. 攻击者立即更改 Apple ID 密码
4. 攻击者关闭"查找我的"
5. 攻击者获取所有数据
→ 总时间：几分钟

有失窃设备保护（在陌生位置）：
1. 攻击者获取设备
2. 胁迫用户用 Face ID 解锁
3. 攻击者尝试更改 Apple ID 密码
4. 系统要求等待 1 小时
5. 用户有时间远程锁定/擦除设备
6. 1 小时后攻击者需要再次生物识别
7. 用户可在此期间报警或远程擦除
→ 攻击失败概率：极高

关键安全增益：
→ 1 小时延迟给受害者反应时间
→ 可远程锁定/擦除设备
→ 可联系 Apple 支持
→ 可报警
→ 攻击者无法立即获取数据
```

### 8.4 熟悉位置的机器学习

```
熟悉位置判定机制：

iOS 使用设备端机器学习判定"熟悉位置"：

1. 数据收集（端侧）
   → 记录设备常用位置
   → 家、办公室、常去地点
   → 所有数据在设备本地处理

2. 模型训练（端侧）
   → Core ML 模型学习位置模式
   → 识别经常停留的位置
   → 不上传到云端

3. 实时判定（端侧）
   → 当前位置与学习模型比较
   → 判定是否为"熟悉位置"
   → 实时决策，无网络延迟

4. 隐私保护
   → 位置数据不离开设备
   → 模型不上传到 Apple
   → 不与其他服务共享
```

## 12. Keybag 与数据保护类别

### 12.1 Keybag 架构

Keybag 是 iOS 管理加密密钥的核心组件：

```
Keybag 结构：

┌─────────────────────────────────────────┐
│              Keybag                      │
├─────────────────────────────────────────┤
│                                          │
│  ┌──────────────────────────────────┐   │
│  │         类密钥 (Class Keys)       │   │
│  │                                  │   │
│  │  ┌────────────────────────────┐ │   │
│  │  │ 完整保护 (Complete)         │ │   │
│  │  │ → 设备锁定时不可访问        │ │   │
│  │  │ → 需要密码解锁              │ │   │
│  │  └────────────────────────────┘ │   │
│  │                                  │   │
│  │  ┌────────────────────────────┐ │   │
│  │  │ 除非打开 (UnlessOpen)       │ │   │
│  │  │ → 锁定后已打开文件可写入    │ │   │
│  │  │ → 不能重新打开              │ │   │
│  │  └────────────────────────────┘ │   │
│  │                                  │   │
│  │  ┌────────────────────────────┐ │   │
│  │  │ 首次解锁后 (UntilFirstAuth) │ │   │
│  │  │ → 首次密码解锁后始终可访问  │ │   │
│  │  │ → 重启后需要密码            │ │   │
│  │  └────────────────────────────┘ │   │
│  │                                  │   │
│  │  ┌────────────────────────────┐ │   │
│  │  │ 无保护 (None)               │ │   │
│  │  │ → 始终可访问                │ │   │
│  │  │ → 仅用于非敏感数据          │ │   │
│  │  └────────────────────────────┘ │   │
│  └──────────────────────────────────┘   │
│                                          │
│  ┌──────────────────────────────────┐   │
│  │         系统密钥                   │   │
│  │  → 系统功能所需                   │   │
│  │  → 不保护用户数据                 │   │
│  └──────────────────────────────────┘   │
│                                          │
└─────────────────────────────────────────┘
```

### 12.2 数据保护类别与锁定状态

| 保护类别 | 解锁状态 | 锁定状态 | 延迟锁定 | 擦除后 |
|----------|----------|----------|----------|--------|
| 完整保护 | 可访问 | 不可访问 | 不可访问 | 密钥销毁 |
| 除非打开 | 可读写 | 已打开可写 | 已打开可写 | 密钥销毁 |

### 12.3 锁定对数据访问的影响

```
设备锁定时的数据访问：

┌─────────────────────────────────────────┐
│  设备锁定                                │
│                                          │
│  完整保护数据：                           │
│  [加密] → 密钥在 Secure Enclave          │
│  → 不可访问                              │
│  → 即使物理提取闪存也无法解密            │
│                                          │
│  除非打开数据：                           │
│  [已打开文件] → 可继续写入               │

│                                          │
│  首次解锁后数据：                         │

│                                          │
└─────────────────────────────────────────┘
```

## 13. 生物识别降级与密码强制

### 13.1 生物识别降级的安全设计

iOS 定期要求密码而非生物识别，这是有意为之的安全设计：

```
密码强制触发条件：

1. 设备重启后
   → 首次解锁必须使用密码
   → 原因：重启后安全会话未建立
   → 密码验证建立密钥链

2. 48 小时未使用密码解锁
   → 必须使用密码
   → 原因：定期验证用户知道密码
   → 防止仅依赖生物识别

3. 生物识别变更后
   → 必须使用密码确认
   → 原因：验证授权用户同意变更
   → 防止未授权添加面容/指纹

4. 紧急锁定后
   → 必须使用密码
   → 原因：用户主动要求
   → 生物识别被禁用

5. 远程锁定后
   → 必须使用密码
   → 原因：远程指令要求
   → 生物识别被禁用

6. 5 次生物识别失败
   → 回退到密码
   → 原因：生物识别可能不可靠
   → 密码作为后备
```

| 维度 | 密码 | Face ID | Touch ID |
|------|------|---------|----------|

## 16. 攻击场景与防御矩阵

### 16.1 场景 1：设备被盗

```
攻击：窃贼获取设备，尝试解锁

防御层次：
1. 设备锁定 → 需要密码/生物识别
2. 强密码 → 暴力破解不可行
3. 激活锁 → 无法重新激活
4. "查找我的" → 可远程追踪/擦除
5. 失窃设备保护 → 陌生位置 1 小时延迟

结果：攻击失败
→ 窃贼无法访问数据
→ 设备无法重新使用
→ 可远程追踪和擦除
```

### 16.2 场景 2：胁迫解锁

```
攻击：攻击者胁迫用户解锁设备

防御层次：
1. 紧急锁定 → 5 次点击禁用生物识别
2. 失窃设备保护 → 陌生位置 1 小时延迟
3. 强密码 → 可拒绝透露
4. 远程擦除 → 可提前设置

缓解措施：
→ 用户可快速按 5 次侧边按钮
→ 生物识别禁用，需要密码
→ 在陌生位置，敏感操作延迟 1 小时
→ 用户有时间远程擦除或报警

结果：攻击部分成功（设备解锁）但数据受保护
```

### 16.3 场景 3：执法扣押

```
攻击：执法机构扣押设备，使用取证工具提取

防御层次：
1. USB 限制模式 → 锁定 1 小时后禁止 USB 数据
2. 强密码 → 暴力破解不可行
3. 自动擦除 → 10 次失败后销毁数据
4. 锁定模式 → 禁止配置文件/MDM
5. 高级数据保护 → iCloud 数据端到端加密

结果：取决于多种因素
→ 如果设备锁定 > 1 小时：USB 限制模式阻止取证工具
→ 如果有零日漏洞：可能绕过某些限制
→ 如果密码足够强：暴力破解不可行
→ 如果启用自动擦除：数据可能已销毁
```

### 16.4 场景 4：远程攻击

```
攻击：攻击者通过网络远程尝试破解密码

防御：
→ 远程无法直接访问锁屏界面
→ 需要物理访问设备
→ 网络攻击无法绕过 Secure Enclave
→ 需要零日漏洞远程执行代码

结果：远程暴力破解不可行
→ 锁屏密码验证在设备本地
→ 不通过网络传输
→ 远程攻击者无法尝试密码
```

### 16.5 防御矩阵总结

| 攻击类型 | 强密码 | USB 限制 | 自动擦除 | 失窃保护 | 锁定模式 | 综合效果 |
|----------|--------|----------|----------|----------|----------|----------|
| 机会主义盗窃 | ✓ | ✓ | ✓ | ✓ | - | 极高 |
| 熟人跟踪 | ✓ | ✓ | ✓ | ✓ | - | 极高 |
| 胁迫解锁 | ✓ | - | - | ✓ | ✓ | 高 |
| 执法取证 | ✓ | ✓ | ✓ | - | ✓ | 高-极高 |
| 国家级攻击 | ✓ | ✓ | ✓ | ✓ | ✓ | 中-高 |
| 远程攻击 | ✓ | - | - | - | - | 极高 |

## 17. Apple ID 防暴力破解

### 17.1 Apple ID 账户保护

Apple ID 有独立的防暴力破解机制：

```
Apple ID 登录保护：

1. 密码尝试限制
   → 多次失败后要求验证码
   → 多次失败后临时锁定账户
   → 多次失败后要求账户恢复

2. 双重认证
   → 即使知道密码，也需要受信任设备验证码
   → 验证码 6 位，有效期 5 分钟
   → 每次登录生成新验证码

3. 账户锁定
   → 检测到异常活动后锁定
   → 需要通过账户恢复流程解锁
   → 恢复可能需要等待数天

4. 安全通知
   → 登录新设备时通知
   → 密码变更时通知
   → 安全设置变更时通知
```

### 17.2 双重认证防暴力破解

```
双重认证流程：

1. 输入 Apple ID + 密码
   → 密码正确？
   → 否：密码错误提示
   → 是：继续

2. 请求验证码
   → 向受信任设备发送验证码
   → 验证码 6 位数字
   → 有效期 5 分钟

3. 输入验证码
   → 验证码正确？
   → 否：拒绝登录
   → 是：登录成功

安全属性：
→ 仅知道密码不够
→ 需要物理访问受信任设备
→ 验证码一次性，无法重用
→ 每次登录生成新验证码
→ 攻击者需要密码 + 受信任设备
```
