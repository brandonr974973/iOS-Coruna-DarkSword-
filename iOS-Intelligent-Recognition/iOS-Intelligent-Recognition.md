## 1. 概述

iOS 智能识别是指 Apple 移动操作系统中集成的一系列基于机器学习、计算机视觉、信号处理和模式识别技术的智能感知能力。这些技术使设备能够"理解"用户的面部、指纹、文字、图像、语音、手写、环境和空间信息，将原始传感器数据转化为结构化、可操作的高层语义。

### 1.1 技术范畴

iOS 智能识别涵盖以下核心领域：

| 领域 | 技术 | 核心能力 |
|------|------|----------|
| 生物特征 | Face ID / Touch ID | 3D 面部识别、电容指纹识别 |
| 文字识别 | Live Text / Vision | 实时 OCR、多语言文本检测 |
| 视觉智能 | Visual Lookup / Visual Intelligence | 物体识别、场景理解、图像搜索 |
| 语音识别 | Siri / Speech Framework | 语音转文字、语义理解 |
| 手写识别 | Scribble / VisionKit | 手写体转印刷体 |
| 空间感知 | ARKit / LiDAR | 深度估计、平面检测、场景重建 |
| 图像分析 | Core ML / Create ML | 自定义模型推理、图像分类 |
| 文档处理 | VNDocumentCameraViewController | 文档边缘检测、透视矫正 |
| 照片智能 | 记忆、搜索、人物分组 | 基于内容的照片组织与检索 |

### 1.2 设计哲学

Apple 的智能识别技术遵循以下设计原则：

**端侧优先（On-Device First）**：绝大多数识别任务在设备本地完成，不依赖云端。这确保了低延迟、离线可用性和隐私保护。Apple Silicon 的 Neural Engine 为端侧推理提供了专用硬件加速。

**隐私内建（Privacy by Design）**：生物特征数据（Face ID 模板、Touch ID 指纹）存储在 Secure Enclave 中，永远不会离开设备或上传到 Apple 服务器。照片识别在设备端完成，iCloud 同步使用端到端加密。

**传感器融合（Sensor Fusion）**：智能识别不是单一传感器的输出，而是多个传感器数据的融合结果。例如 Face ID 结合了红外摄像头、点阵投影器和 RGB 摄像头；ARKit 融合了摄像头、陀螺仪、加速度计和 LiDAR。

**框架化（Framework-based）**：Apple 将智能识别能力封装为开发者友好的框架（Vision、Speech、NaturalLanguage、ARKit、Core ML），使第三方应用能够复用这些能力。

### 1.3 硬件基础

iOS 智能识别依赖以下硬件组件：

| 硬件 | 功能 | 首次引入 |
|------|------|----------|
| TrueDepth 摄像头系统 | 3D 面部扫描（Face ID） | iPhone X (2017) |
| 电容指纹传感器 | 指纹识别（Touch ID） | iPhone 5s (2013) |
| Neural Engine | 神经网络推理加速 | A11 Bionic (2017) |
| LiDAR 扫描仪 | dToF 深度测量 | iPad Pro 2020 |
| 超宽带芯片（U1/U2） | 空间感知与精确查找 | iPhone 11 (2019) |
| 图像信号处理器（ISP） | 计算摄影与实时图像处理 | 历代 A 系列芯片 |

### 1.4 软件框架栈

```
┌─────────────────────────────────────────────┐
│              应用层（Apps）                    │
├─────────────────────────────────────────────┤
│  Vision │ Speech │ ARKit │ NaturalLanguage   │
│  VisionKit │ Core ML │ Create ML            │
├─────────────────────────────────────────────┤
│         Accelerate / Metal / MetalPS         │
├─────────────────────────────────────────────┤

├─────────────────────────────────────────────┤
│    TrueDepth │ Touch ID │ LiDAR │ Camera     │

└─────────────────────────────────────────────┘
```

## 2. iOS 智能识别技术体系架构

### 2.1 分层架构

iOS 智能识别采用清晰的分层架构：

**第一层：传感器采集层**

负责原始数据的获取。包括摄像头帧采集、麦克风音频流、IMU 惯性数据、LiDAR 深度图、Touch ID 电容图像等。这一层通过 AVFoundation、CoreMotion 等框架暴露给上层。

**第二层：预处理层**

对原始传感器数据进行校正、降噪、归一化。例如摄像头图像的白平衡校正、畸变矫正；音频的降噪和回声消除；深度图的去噪和补全。

**第三层：特征提取层**

从预处理后的数据中提取用于识别的特征向量。例如 Face ID 从红外图像中提取面部深度特征；Vision 框架从图像中提取边缘、角点和语义分割特征。

**第四层：模型推理层**

将特征向量输入预训练的机器学习模型，输出识别结果。这一层由 Core ML 和 Neural Engine 协同完成。模型包括卷积神经网络（CNN）、Transformer、循环神经网络（RNN）等。

**第五层：后处理与决策层**

对模型输出进行后处理，包括非极大值抑制（NMS）、置信度阈值判定、多帧融合、时序平滑等。最终输出结构化的识别结果。

### 2.2 数据流架构

```
传感器 → 预处理 → 特征提取 → 模型推理 → 后处理 → 应用
  ↑                                              ↓
  └──────────── 反馈与自适应 ←────────────────────┘
```

关键数据流特性：

- **流水线并行**：传感器采集、预处理和推理可以流水线化执行，降低端到端延迟
- **多帧融合**：对同一场景的多帧数据进行融合，提高识别准确率
- **自适应采样**：根据场景复杂度动态调整处理帧率和分辨率
- **热管理**：持续监控设备温度，在过热时降低处理负载

### 2.3 框架间协作

iOS 智能识别框架之间存在密切的协作关系：

- **Vision + Core ML**：Vision 框架负责图像预处理和结果后处理，Core ML 负责模型推理
- **ARKit + Vision + Core ML**：ARKit 提供空间定位，Vision 提供 2D 图像理解，Core ML 提供自定义识别
- **Speech + NaturalLanguage**：Speech 将语音转为文字，NaturalLanguage 对文字进行语义分析
- **VisionKit + Vision**：VisionKit 提供高层文档扫描 UI，底层使用 Vision 进行边缘检测和 OCR

## 3. 生物特征识别：Face ID

### 3.1 系统组成

Face ID 是 Apple 的 3D 面部识别系统，由 TrueDepth 摄像头系统驱动。该系统包含以下组件：

| 组件 | 功能 | 规格 |
|------|------|------|
| 红外摄像头（IR Camera） | 捕获红外面部图像 | 686×486 分辨率 |
| 点阵投影器（Dot Projector） | 投射约 30,000 个红外点 | 创建面部深度图 |
| 泛光感应元件（Flood Illuminator） | 发射均匀红外光 | 暗光环境补光 |
| RGB 摄像头 | 捕获可见光图像 | 用于注视检测和辅助验证 |
| 环境光传感器 | 检测环境光照条件 | 辅助曝光控制 |

### 3.2 工作流程

Face ID 的识别流程分为注册和认证两个阶段：

**注册阶段（Enrollment）**：

1. 用户头部缓慢转动，系统从多个角度采集面部数据
2. 点阵投影器投射约 30,000 个不可见红外点
3. 红外摄像头捕获点阵图案的变形，计算面部深度图
4. 系统从深度图中提取面部几何特征
5. 生成面部数学模型（模板），存储在 Secure Enclave 中
6. 模板经过 AES 加密，使用 Secure Enclave 内部的密钥保护

**认证阶段（Authentication）**：

1. 用户注视设备，接近传感器或抬手动作触发 Face ID
2. 泛光感应元件发射红外光（暗光环境下）
3. 点阵投影器投射红外点阵
4. 红外摄像头捕获反射的点阵图案
5. 计算当前面部深度图
6. 与 Secure Enclave 中存储的模板进行比对
7. 计算匹配分数，与自适应阈值比较
8. 匹配成功则解锁设备或确认身份

### 3.3 安全指标

| 指标 | 数值 | 说明 |
|------|------|------|
| 随机解锁概率 | 1/1,000,000 | 单次随机面部尝试成功的概率 |
| 双胞胎/近亲概率 | 1/10,000 | 同卵双胞胎或相似近亲的误识率 |
| 模板存储位置 | Secure Enclave | 不离开安全芯片 |
| 模板加密 | AES-256 | 硬件密钥保护 |
| 注视检测 | 必需 | 要求用户睁眼注视设备 |
| 注意力感知 | 支持 | 未注视时不显示通知内容 |

### 3.4 反欺骗机制

Face ID 包含多层反欺骗（Presentation Attack Detection, PAD）机制：

**深度验证**：攻击者无法使用照片或视频欺骗，因为 Face ID 检测的是 3D 深度信息而非 2D 图像。平面照片没有深度变化，视频无法提供正确的红外反射特性。

**红外反射分析**：真实皮肤和面具/硅胶模型对红外光的反射特性不同。Face ID 分析红外反射光谱以区分活体和非活体。

**注视检测**：要求用户睁眼并注视设备。这防止了在用户不知情（如睡眠中）时被解锁。虹膜和瞳孔的红外反射特征也参与活体判断。

**机器学习模型**：Apple 训练了专门的神经网络来检测面部欺骗攻击，包括面具、3D 打印面部模型和深度伪造攻击。该模型持续更新。

**模板更新**：Face ID 在每次成功认证后微调模板，适应用户外貌的渐变（如胡须生长、化妆变化）。这种自适应机制也增加了持续欺骗的难度。

### 3.5 技术演进

| 版本 | 引入设备 | 改进 |
|------|----------|------|
| Face ID v1 | iPhone X | 初始版本，30K 点阵 |
| Face ID v2 | iPhone 12 | 改进低光性能，扩大识别角度 |
| Face ID v3 | iPhone 14 | 改进口罩场景识别 |
| Face ID（横屏） | iPhone 14+ | 支持横屏方向认证 |
| 口罩模式 | iOS 15.4 | 眼部区域识别，适配口罩场景 |

### 3.6 安全限制与已知问题

**强制面容录入**：执法机构可能要求用户配合解锁。可通过快速按五次侧键临时禁用 Face ID，强制要求密码。

**法律强制场景**：部分司法管辖区可能强制要求生物特征解锁。密码在法律保护上通常优于生物特征。

**近亲误识**：同卵双胞胎的误识率显著高于普通人群。Apple 建议双胞胎用户使用密码认证。

**环境干扰**：极端强光、特定太阳镜和医疗面罩可能影响识别性能。

## 4. 生物特征识别：Touch ID

### 4.1 技术原理

Touch ID 基于电容式指纹传感技术：

**传感器结构**：Touch ID 传感器由一组微小的电容极板阵列组成。每个极板测量指纹脊（接触传感器表面）和谷（不接触）之间的电容差异。

**图像生成**：电容差异被转换为 500 PPI 分辨率的灰度指纹图像。传感器能够穿透表皮层读取真皮层的指纹图案。

**特征提取**：从指纹图像中提取 minutiae 特征点（脊的端点和分叉点），以及脊的走向、曲率等纹理特征。

**模板匹配**：提取的特征被编码为数学模板，存储在 Secure Enclave 中。认证时将当前采集的特征与存储模板进行匹配。

### 4.2 传感器类型演进

| 代次 | 设备 | 特点 |
|------|------|------|
| 第一代 | iPhone 5s | 蓝宝石玻璃覆盖，不锈钢检测环 |
| 第二代 | iPhone 6s | 更快的识别速度，更大的传感器面积 |
| Home Button 集成 | iPhone 7-8 | 固态按钮设计，触感反馈 |
| 侧边集成 | iPad Air/mini | 集成在电源键中 |

### 4.3 安全架构

Touch ID 的安全架构与 Face ID 共享相同的安全基础：

- 指纹模板仅存储在 Secure Enclave 内
- 模板经过加密，使用 Secure Enclave 独有的密钥
- 指纹图像在传感器处理完成后立即销毁，不保留原始图像
- 认证决策在 Secure Enclave 内部完成，AP 处理器只接收"成功/失败"结果
- 每次认证的匹配算法引入随机化，防止侧信道攻击

### 4.4 与 Face ID 的对比

| 维度 | Touch ID | Face ID |
|------|----------|---------|
| 生物特征类型 | 指纹（2D 纹理） | 面部（3D 几何） |
| 传感器类型 | 电容式 | 红外结构光 |
| 误识率 | 1/50,000 | 1/1,000,000 |
| 湿手影响 | 显著 | 无影响 |
| 口罩影响 | 无影响 | 需要切换到眼部模式 |
| 多指/多角度 | 支持（最多 5 个指纹） | 支持（多角度注册） |
| 安全性 | 高 | 更高（3D + 活体检测） |

## 5. 光学字符识别（OCR）：Live Text

### 5.1 技术概述

Live Text 是 iOS 15 引入的实时文字识别功能，能够在相机取景器、照片和屏幕截图中识别并提取文字。

### 5.2 技术栈

Live Text 基于 Vision 框架的 `VNDetectTextRectanglesRequest` 和 `VNRecognizeTextRequest` API：

**文本检测（Text Detection）**：

- 使用轻量级卷积神经网络检测图像中的文本区域
- 输出文本行的边界框（bounding box）
- 支持任意方向的文本（水平、垂直、倾斜）
- 处理速度极快，适合实时预览

**文本识别（Text Recognition）**：

- 使用 CRNN（卷积循环神经网络）或 Transformer 架构识别文本内容
- 支持多语言识别，包括中文、日文、韩文、阿拉伯文等
- 支持手写体和印刷体
- 输出识别文本及其置信度

**文本描述符增强**：

- 识别结果附带数据类型描述符（Data Detector）
- 自动识别电话号码、URL、地址、日期、电子邮件等
- 点击识别出的电话号码可直接拨打，URL 可直接打开

### 5.3 实时识别流程

```
相机帧 → 图像预处理 → 文本区域检测 → 文本识别 → 数据类型检测 → UI 叠加
   ↑                                                          ↓
   └──────────── 下一帧 ←──────────────────────────────────────┘
```

关键优化：

- **帧跳过**：不是每帧都处理，而是在检测到场景变化时触发识别
- **区域缓存**：已识别的文本区域在连续帧中跟踪，避免重复计算
- **增量更新**：只重新识别变化的区域，保持稳定的识别结果
- **低功耗模式**：电池低时降低处理频率

### 5.4 支持的语言

Live Text 支持超过 100 种语言的文本识别，主要语言组包括：

| 语言组 | 代表语言 |
|--------|----------|
| 拉丁系 | 英语、法语、德语、西班牙语、意大利语、葡萄牙语 |
| 中日韩 | 简体中文、繁体中文、日语、韩语 |
| 阿拉伯系 | 阿拉伯语、希伯来语、波斯语 |
| 印度系 | 印地语、泰米尔语、泰卢固语 |
| 西里尔系 | 俄语、乌克兰语 |

### 5.5 Live Text in Videos

iOS 17 扩展了 Live Text 能力，支持在暂停的视频帧中识别文本。这要求更强的实时处理能力，因为视频帧的运动模糊和低分辨率增加了识别难度。

### 5.6 开发者接口

```swift
// 文本检测
let request = VNDetectTextRectanglesRequest()
request.reportComponentRects = true

// 文本识别
let recognizeRequest = VNRecognizeTextRequest()
recognizeRequest.recognitionLevel = .accurate  // 或 .fast
recognizeRequest.recognitionLanguages = ["zh-Hans", "en-US"]
recognizeRequest.usesLanguageCorrection = true
```

## 6. 视觉查找：Visual Lookup

### 6.1 功能概述

Visual Lookup 是 iOS 15 引入的图像内容识别功能，允许用户在照片中长按照片识别物体、地标、植物、动物等，并提供相关信息和操作选项。

### 6.2 识别类别

| 类别 | 识别内容 | 提供的操作 |
|------|----------|------------|
| 地标 | 著名建筑、景点 | 名称、维基百科链接、导航 |
| 植物 | 花卉、树木 | 植物种类、养护信息 |
| 动物 | 宠物品种、野生动物 | 品种信息 |
| 艺术品 | 绘画、雕塑 | 艺术家、作品信息 |
| 书籍 | 书籍封面 | 书名、作者、购买链接 |
| 商品 | 服装、家具 | 搜索相似商品 |
| 昆虫 | 昆虫种类 | 种类信息 |

### 6.3 技术实现

Visual Lookup 使用多层级识别管线：

1. **显著性检测**：首先识别图像中的显著区域（前景物体），排除背景干扰
2. **物体检测**：使用目标检测模型定位图像中的物体及其类别
3. **细粒度分类**：对检测到的物体进行细粒度分类（如从"狗"细化到"金毛寻回犬"）
4. **特征嵌入**：将物体编码为高维特征向量
5. **知识图谱匹配**：将特征向量与 Apple 的知识图谱进行匹配，获取语义信息
6. **端侧与云端混合**：常见物体在端侧识别，罕见物体可能使用云端增强

### 6.4 隐私处理

- 图像分析在设备端完成
- 如果端侧无法识别，可能将图像的特征向量（非原始图像）发送到服务器
- 用户可以选择不启用此功能
- 处理结果不持久化到 Apple 服务器

## 9. 人脸识别与分组

### 9.1 照片应用中的人脸识别

iOS 照片应用自动执行以下人脸识别流程：

1. **人脸检测**：扫描照片库中的所有照片，检测其中的人脸
2. **特征提取**：从每个人脸区域提取面部特征向量（embedding）
3. **聚类分组**：使用聚类算法将相似的面部特征归为同一人物
4. **命名关联**：用户可以为人物分组命名，关联到联系人
5. **持续学习**：新照片自动加入已有分组或创建新分组

### 9.2 技术细节

**特征向量**：每个人脸被编码为一个 128 维或更高维的特征向量。这个向量捕获了面部的几何结构和外观特征，对姿态、光照和表情变化具有一定的鲁棒性。

**聚类算法**：使用基于密度的聚类算法（类似 DBSCAN），能够自动确定人物数量，不需要预先指定。算法需要处理以下挑战：
- 同一个人不同年龄的外貌变化
- 不同人在相似角度下的混淆
- 低质量照片中的模糊人脸

**隐私保护**：
- 所有人脸识别在设备端完成
- 人脸数据不上传到 Apple 服务器
- iCloud 照片同步时，人脸分组数据使用端到端加密传输

### 9.3 Vision 框架 API

```swift
// 人脸检测
let faceDetection = VNDetectFaceRectanglesRequest()

// 人脸 Landmark 检测
let faceLandmarks = VNDetectFaceLandmarksRequest()
// 返回 76 个特征点：眼睛、鼻子、嘴巴、眉毛、面部轮廓

// 人脸特征提取（用于自定义聚类）
let faceObservation = /* 从人脸检测结果获取 */
let facePrint = try faceObservation.facePrint()
// facePrint 是可用于比较和聚类的人脸特征向量
```

## 10. 语音识别与 Siri 语音理解

### 10.1 Speech 框架

Speech 框架提供端侧和云端混合的语音识别能力：

**端侧识别**：

- 基于 Transformer 的端到端语音识别模型
- 支持离线使用
- 延迟低，隐私性好
- 支持约 20 种主要语言

**云端增强**：

- 更复杂的语言模型提供更高的准确率
- 需要网络连接
- 支持更多语言和方言
- 持续改进的声学模型

### 10.2 语音识别流程

```
麦克风 → 音频采集（16kHz/48kHz）→ VAD（语音活动检测）
  → 降噪/AEC → 声学特征提取（MFCC/Mel 频谱）
  → 声学模型 → 语言模型 → 文本输出
```

**语音活动检测（VAD）**：区分语音和静音/噪声段，只在检测到语音时启动识别管线，节省计算资源。

**声学模型**：将音频特征映射到音素或子词单元。Apple 使用基于 Conformer（卷积+Transformer）的声学模型，在端侧和云端使用不同规模的模型。

**语言模型**：将音素序列转换为最可能的文字序列。Apple 的语言模型经过大量文本训练，支持上下文感知（如联系人名称、应用内容）。

### 10.3 Siri 语音理解

Siri 的语音理解在 iOS 18 中经历了重大升级，集成了 Apple Intelligence：

**传统 Siri（2011-2023）**：
- 基于意图分类 + 槽位填充
- 预定义的意图集合
- 有限的上下文理解

**Siri with Apple Intelligence（2024+）**：
- 基于大语言模型的自然语言理解
- 多轮对话上下文保持
- 屏幕内容理解（Screen Awareness）
- 跨应用操作（App Intents 集成）
- 个人上下文感知（联系人、日历、邮件等）

### 10.4 听写（Dictation）

iOS 的系统级听写功能：

- 支持多语言混合识别（如中英文混合）
- 自动标点符号插入
- 语音命令（"换行"、"删除"、"句号"等）
- 实时流式输出
- 端侧优先处理

## 18. 智能识别的隐私与安全架构

### 18.1 隐私保护原则

Apple 对智能识别的隐私保护遵循以下原则：

**数据最小化**：只采集识别所需的最少数据。例如 Face ID 不存储面部图像，只存储数学模板。

**端侧处理**：尽可能在设备端完成所有识别处理。只有在端侧无法满足需求时才使用云端，且只传输必要的特征数据。

**透明与同意**：每个智能识别功能都需要用户明确授权。相机、麦克风、照片库等传感器访问都需要用户许可。

**数据隔离**：不同应用和功能的识别数据相互隔离。一个应用无法访问另一个应用收集的识别数据。

### 18.2 Secure Enclave 的角色

Secure Enclave 在智能识别安全中扮演核心角色：

```
┌─────────────────────────────────────────┐
│            Secure Enclave                │
│  ┌──────────┐  ┌──────────────────┐     │
│  │ 密钥管理  │  │ 生物特征模板存储  │     │
│  │          │  │ (Face ID/Touch ID)│     │
│  └──────────┘  └──────────────────┘     │
│  ┌──────────────────────────────────┐   │
│  │     认证决策引擎                   │   │
│  │  (匹配 + 反欺骗 + 速率限制)       │   │
│  └──────────────────────────────────┘   │
│  ┌──────────────────────────────────┐   │
│  │     安全启动链 + 完整性验证        │   │
│  └──────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

### 18.3 权限模型

iOS 对智能识别相关的传感器实施严格的权限控制：

| 权限 | 说明 | 触发时机 |
|------|------|----------|
| 相机 | 访问摄像头 | 首次使用时弹窗 |
| 麦克风 | 访问麦克风 | 首次使用时弹窗 |
| 照片库 | 访问照片 | 首次访问时弹窗 |
| 人脸数据 | Face ID 认证 | 每次调用时 |
| 位置 | GPS 数据 | 首次使用时弹窗 |
| 联系人 | 通讯录数据 | 首次访问时弹窗 |

### 18.4 App Tracking Transparency

ATT 框架限制了应用对用户行为的追踪：

- 应用必须获得用户许可才能追踪
- 智能识别结果不能被用于跨应用追踪
- 设备端识别结果不会与广告标识符关联

### 18.5 差分隐私

Apple 在部分智能识别功能中使用差分隐私：

- 匿名化统计数据（如新词流行度）
- 添加可控噪声保护个体隐私
- 用于改进系统级模型而不泄露个人信息

## 19. 智能识别的攻击面与安全风险分析

### 19.1 生物特征攻击

**Face ID 攻击向量**：

| 攻击方式 | 难度 | 有效性 |
|----------|------|--------|
| 照片攻击 | 低 | 无效（需要 3D） |
| 视频攻击 | 中 | 无效（红外反射不匹配） |
| 3D 面具 | 高 | 极低概率成功 |
| 深度伪造 | 高 | 无效（需要物理 3D） |
| 双胞胎攻击 | N/A | 有一定成功率 |
| Secure Enclave 攻击 | 极高 | 理论上可能，实际极难 |

**Touch ID 攻击向量**：

| 攻击方式 | 难度 | 有效性 |
|----------|------|--------|
| 硅胶指纹模具 | 中 | 可能成功 |
| 导电墨水打印指纹 | 中 | 可能成功 |
| 残留指纹提取 | 高 | 条件性成功 |
| Secure Enclave 攻击 | 极高 | 理论上可能 |

### 19.2 OCR 攻击

**对抗性文本攻击**：

- 在图像中添加人眼不可见的扰动，使 OCR 模型产生错误识别
- 例如将"转账 1000 元"识别为"转账 100 元"
- 影响银行应用、支付应用中的金额识别

**钓鱼攻击**：

- 使用 Live Text 识别伪造的 URL
- 用户可能信任"系统识别"的结果
- 需要确保 URL 验证不依赖 OCR 结果

### 19.3 语音识别攻击

**语音注入攻击**：

- 通过恶意应用向语音识别 API 注入预录制的音频
- 绕过麦克风访问限制
- 可能触发意外的 Siri 命令

**超声波攻击**：

- 使用人耳不可闻的超声波触发语音识别
- 部分语音识别系统对超声波敏感
- 需要硬件层面防护

**对抗性音频攻击**：

- 在音频中添加人耳不可闻的扰动
- 使语音识别产生错误的转写结果
- 可能影响语音命令的准确性

### 19.4 图像识别攻击

**对抗性样本**：

- 在图像中添加精心设计的扰动
- 使图像分类模型产生错误判断
- 例如将"停车标志"识别为"限速标志"

**模型逆向**：

- 通过反复查询推断模型的行为
- 可能提取模型的决策边界
- 用于构造更有效的对抗性攻击

### 19.5 位置与空间攻击

**GPS 欺骗**：

- 伪造 GPS 信号，使设备误报位置
- 影响基于位置的智能识别功能
- 需要多源定位交叉验证

**AR 空间攻击**：

- 在 AR 场景中放置恶意虚拟内容
- 利用 ARKit 的平面检测放置钓鱼内容
- 用户可能信任 AR 叠加的信息

## 20. 智能识别的性能优化与资源管理

### 20.1 计算资源管理

iOS 智能识别需要在有限的移动设备资源下运行：

**Neural Engine 调度**：

- 多个识别任务共享 Neural Engine
- 系统根据优先级分配 ANE 时间片
- 前台应用优先于后台任务

**热管理**：

- 持续监控 CPU/GPU/ANE 温度
- 达到温度阈值时降低处理负载
- 可能降低识别帧率或精度

**内存管理**：

- 模型加载到内存后复用
- 不活跃的模型自动卸载
- 内存压力时释放非关键模型

### 20.2 能效优化

| 策略 | 说明 |
|------|------|
| 帧率自适应 | 场景稳定时降低处理帧率 |
| 分辨率自适应 | 简单场景使用低分辨率 |
| 模型级联 | 先用轻量模型筛选，再用重量模型精判 |
| 按需加载 | 只在需要时加载特定模型 |
| 批处理 | 合并多个推理请求 |

### 20.3 延迟优化

端到端延迟是用户体验的关键指标：

| 功能 | 目标延迟 | 优化手段 |
|------|----------|----------|
| Face ID 解锁 | < 500ms | ANE 加速 + 流水线 |
| Live Text | < 200ms | 帧跳过 + 区域缓存 |
| 语音识别 | < 300ms | 流式推理 |
| 物体检测 | < 100ms | 模型量化 + ANE |
| AR 平面检测 | < 50ms | LiDAR + 专用硬件 |
