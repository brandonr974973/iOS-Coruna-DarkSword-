## 一、结论先行

FORCEDENTRY 不是一项孤立的技术突破，而是商业监控产业、iOS 安全攻防演进与地缘政治监控需求三重力量交汇的产物。

核心背景事实：

- **产业背景**：全球商业监控产业在 2010-2020 年间从零散市场发展为估值数十亿美元的成熟产业
- **公司背景**：NSO Group 从 2010 年的小型创业公司发展为全球最具争议性的监控技术供应商
- **技术背景**：Pegasus 平台经历了从点击式（2016）到零点击（2021）的四代技术演进
- **政治背景**：2021 年 7 月 Pegasus Project 大规模泄露引发全球监控丑闻，FORCEDENTRY 在此背景下被发现
- **受害者背景**：巴林政府使用 FORCEDENTRY 攻击本国人权活动家
- **防御背景**：FORCEDENTRY 直接催生了 Apple 锁定模式（Lockdown Mode），改变了 iOS 安全架构方向
- **法律背景**：Apple 起诉 NSO Group，美国商务部将 NSO Group 列入实体清单

FORCEDENTRY 的技术复杂度只有放在这个宏观背景下才能被充分理解——它不只是一个漏洞利用，而是一个价值数十亿美元产业的核心产品的关键技术节点。

## 二、商业监控产业的崛起

### 2.1 产业起源

商业监控产业的根源可以追溯到冷战时期的信号情报（SIGINT）传统。冷战结束后，大量情报技术人员流入私营部门，催生了第一批商业监控公司。

```
商业监控产业演进

1990s ─── 冷战结束
    │       情报人员流入私营部门
    │       第一批商业监控公司成立
    │
2000s ─── 反恐战争
    │       政府对监控技术需求激增
    │       以色列成为产业中心
    │       Unit 8200 退伍军人创业潮
    │
2010s ─── 智能手机普及
    │       移动监控成为核心赛道
    │       NSO Group、Circles、Cognyte 等公司崛起
    │       Pegasus 成为行业标杆产品
    │
2020s ─── 丑闻与制裁
            Pegasus Project 泄露
            国际社会加强监管
            产业转入地下与重组
```

### 2.2 以色列：监控技术的摇篮

以色列在全球商业监控产业中占据独特地位，这并非偶然：

| 因素 | 说明 |
|------|------|
| **Unit 8200 人才池** | 以色列国防军 8200 部队（等同于美国 NSA）培养了大量信号情报和网络战人才 |
| **安全需求驱动** | 以色列自身的安全需求催生了先进的监控和网络安全技术 |
| **政府支持** | 以色列国防部对出口监控技术持开放态度，将其作为外交工具 |
| **创业文化** | 以色列强大的科技创业生态为监控公司提供了技术和资金基础 |
| **法律框架** | 以色列对监控技术出口的监管相对宽松（在 2021 年之前） |

NSO Group 的创始人 Shalev Hulio 和 Omri Lavie 正是在这一生态中成长的技术人员。

### 2.3 全球市场需求

商业监控技术的买家主要是各国政府的情报机构和执法部门，需求驱动因素包括：

```
需求驱动力

┌─────────────────────────────────────────────────────────┐
│                                                          │
│  反恐需求                                                │
│  • 2001 年 9/11 后全球反恐压力                           │
│  • 政府需要监控可疑恐怖分子通信                          │
│  • 传统监控手段无法应对加密通信                          │
│                                                          │
│  犯罪侦查                                                │
│  • 有组织犯罪、毒品走私等严重犯罪                        │
│  • 需要实时通信截取能力                                  │
│  • 传统电话窃听向数字监控转型                            │
│                                                          │
│  政治监控（滥用）                                        │
│  • 部分政权监控异见人士和记者                            │
│  • 压制政治反对派                                        │
│  • 这是最具争议的用途                                    │
│                                                          │
│  情报收集                                                │
│  • 国家间间谍活动                                        │
│  • 地缘政治情报需求                                      │

```

### 2.4 产业规模与格局

据估算，全球商业监控产业在 2020 年代初的规模：

| 指标 | 估计值 |
|------|--------|
| **全球市场规模** | 约 120-150 亿美元（含所有监控技术） |
| **移动监控细分** | 约 20-30 亿美元 |
| **主要供应商** | NSO Group、Circles（前 Cellbrite）、Cognyte、Intellexa 等 |
| **已知客户国** | 超过 45 个国家 |
| **单次部署成本** | 50,000 - 650,000 美元（取决于目标数量和功能） |
| **年度维护费** | 通常为初始部署费用的 20-30% |

## 四、Pegasus 平台的技术演进

### 4.1 四代攻击链

Pegasus 不是一成不变的产品，而是一个持续演进的平台。从 2016 年到 2021 年，至少经历了四代重大技术迭代：

```
Pegasus 技术演进

第一代：TRIDENT（2016）
┌──────────────────────────────────────────────┐
│ 攻击向量：SMS 钓鱼链接                        │
│ 交互需求：需要目标点击链接                    │
│ 零日数量：3 个                                │
│ 入口组件：WebKit                              │
│ 特征：首次证明 iOS 可被远程完全攻破           │
│ 局限性：依赖社会工程，成功率不稳定            │
└──────────────────────────────────────────────┘
              │
              ▼
第二代：WhatsApp 攻击（2019）
┌──────────────────────────────────────────────┐
│ 攻击向量：WhatsApp VoIP 调用                  │
│ 交互需求：零点击（无需接听）                  │
│ 零日数量：至少 1 个                           │
│ 入口组件：WhatsApp VoIP 协议栈               │
│ 特征：首次实现零点击远程攻击                  │
│ 局限性：依赖第三方应用，WhatsApp 修补后失效   │
└──────────────────────────────────────────────┘
              │
              ▼
第三代：FORCEDENTRY（2021）
┌──────────────────────────────────────────────┐
│ 攻击向量：iMessage 媒体附件                   │
│ 交互需求：零点击                              │
│ 零日数量：至少 2-3 个                         │
│ 入口组件：CoreGraphics JBIG2 解码器          │
│ 特征：完全绕过 WebKit，攻击面极其隐蔽        │
│ 局限性：技术复杂度极高，成本极高              │
└──────────────────────────────────────────────┘
              │
              ▼
第四代：BLASTPASS（2023）
┌──────────────────────────────────────────────┐
│ 攻击向量：Safari WebKit + PassKit             │
│ 交互需求：零点击                              │
│ 零日数量：2 个                                │
│ 入口组件：WebKit + CoreAnimation             │
│ 特征：首次突破锁定模式                        │
│ 局限性：需要目标设备未更新到最新版本          │
└──────────────────────────────────────────────┘
```

### 4.2 演进驱动力

Pegasus 技术演进的核心驱动力：

| 驱动力 | 说明 |
|--------|------|
| **防御加固** | Apple 持续加固旧攻击面，迫使 NSO Group 寻找新入口 |
| **零交互需求** | 客户需要更高的成功率，零点击远优于点击诱导 |
| **检测规避** | 每次被公开发现后，攻击向量失效，需要更隐蔽的入口 |
| **竞争压力** | 其他监控公司也在研发类似能力 |
| **iOS 更新** | 每次 iOS 大版本更新都会封堵已知漏洞 |

### 4.3 从 WebKit 到 CoreGraphics 的战略转移

这是理解 FORCEDENTRY 背景的关键技术转折点：

```
攻击面转移逻辑

2016-2019：WebKit 时代
┌─────────────────────────────────────────────┐

│  ├── 功能复杂（JavaScript 引擎、DOM 解析等）│
│  ├── 攻击面巨大                              │
│  ├── 被广泛使用（Safari、邮件、iMessage 等） │

│                                              │
└─────────────────────────────────────────────┘

2020-2021：转向非传统攻击面
┌─────────────────────────────────────────────┐
│                                              │

│  ├── 图像编解码器（JBIG2、TIFF 等）         │

│  ├── 音频/视频解码器                         │
│  └── 其他格式解析器                          │
│                                              │
│  优势：                                      │
│  ├── 安全审计稀少                            │
│  ├── 不是 Apple 加固重点                     │
│  ├── 代码相对陈旧                            │
│  ├── 仍在关键处理路径中（iMessage 预览）     │
│  └── 漏洞可以长期保持有效                    │
│                                              │
│  → FORCEDENTRY 是这一战略的巅峰成果          │
│                                              │
└─────────────────────────────────────────────┘
```

### 6.2 巴林人权活动家被攻击事件

2021 年 9 月被 Citizen Lab 发现遭到 FORCEDENTRY 攻击的巴林人权活动家，是这一监控滥用的典型案例。

虽然 Citizen Lab 出于安全考虑未公开受害者的完整身份信息，但已知以下事实：

- 受害者是巴林知名的人权活动家
- 其 iPhone 设备被 Pegasus 间谍软件感染
- 攻击使用了 FORCEDENTRY 零点击 iMessage 攻击链
- 攻击发生在 2021 年 9 月之前
- 设备运行 iOS 14.x 版本

### 6.3 巴林监控生态

巴林对 Pegasus 的使用不是孤立事件，而是其广泛国内监控体系的一部分：

| 监控手段 | 说明 |
|---------|------|
| **通信监控** | 截取电话、短信、电子邮件 |
| **社交媒体监控** | 监控社交媒体活动和在线言论 |
| **Pegasus 部署** | 针对高价值目标使用 Pegasus 进行深度监控 |
| **物理监控** | 跟踪、监视和拘留异见人士 |
| **旅行禁令** | 限制异见人士出境 |
| **国籍撤销** | 撤销部分异见人士的巴林国籍 |

### 6.4 为什么巴林选择 FORCEDENTRY

巴林政府选择使用 FORCEDENTRY 而非其他攻击方式，反映了几个因素：

1. **目标高价值**：人权活动家是最高优先级目标
2. **隐蔽性需求**：零点击攻击不会留下钓鱼链接等可分析的证据
3. **成功率需求**：零点击攻击的成功率远高于需要用户交互的攻击
4. **技术获取能力**：巴林有足够的财力和政治关系获取 NSO Group 最先进的技术
5. **国际监管薄弱**：在 2021 年之前，巴林使用监控技术几乎不受国际约束

## 七、iOS 安全生态的演进与裂缝

### 7.1 iOS 安全架构的演进

理解 FORCEDENTRY 的背景，需要理解 iOS 安全架构在 2021 年时的状态：

```
iOS 安全演进（至 2021 年）

2007 ─── iPhone OS 1.0
│         基础沙盒模型
│         代码签名
│         无第三方应用
│
2008 ─── iPhone OS 2.0
│         App Store 引入
│         应用沙盒强制化
│
2012 ─── iOS 6
│         ASLR 全面启用
│         增强沙盒规则
│
2016 ─── iOS 10
│         增强的密钥派生
│         USB 限制模式（后续版本）
│         KTRR（内核文本只读）
│
2018 ─── iOS 12
│         用户级进程加速（USRJ）

          沙盒模型仍允许 XPC 通信
```

### 7.2 已有的安全缓解机制

到 2021 年，iOS 已经部署了多层安全缓解机制：

| 缓解机制 | 说明 | 对 FORCEDENTRY 的影响 |
|---------|------|---------------------|
| **ASLR** | 地址空间布局随机化 | 增加利用难度，但非不可克服 |
| **PAC** | 指针认证码 | 保护指针不被篡改，但用户态保护有限 |
| **KASLR** | 内核地址空间布局随机化 | 增加内核利用难度 |
| **沙盒** | 进程权限隔离 | 需要额外的沙盒逃逸漏洞 |
| **代码签名** | 强制代码签名验证 | 需要 AMFI 绕过 |
| **KTRR** | 内核代码只读保护 | 防止直接修改内核代码 |
| **PPL** | 页面保护层 | 保护关键内核页面 |

### 7.3 安全架构的裂缝

尽管有这些缓解机制，iOS 安全架构仍存在关键裂缝：

### 8.1 iMessage 作为攻击入口的战略价值

│  • 真正的零点击攻击向量                                  │
│                                                          │

### 8.2 替代方案的局限性

NSO Group 在转向 iMessage 之前，已经用尽了其他主要选项：

| 替代方案 | 局限性 |
|---------|--------|
| **SMS 钓鱼** | 需要用户点击，成功率低，容易被识别和报告 |
| **WhatsApp VoIP** | 2019 年被公开，WhatsApp 修补后失效 |
| **Safari/WebKit** | 被广泛审计，新漏洞保质期短 |
| **水坑攻击** | 需要目标访问特定网站，不可控 |
| **物理接触** | 需要物理获取设备，风险极高 |
| **蜂窝网络攻击（IMSI catcher）** | 只能截取通信，无法入侵设备 |

### 8.3 iMessage 攻击的技术挑战

选择 iMessage 也意味着面对更高的技术挑战：

```
iMessage 攻击技术挑战

1. 格式选择
   └── 需要找到一个在 iMessage 处理路径中、但审计稀少的格式
   └── JBIG2 满足条件：PDF 可以嵌入，iMessage 会自动处理 PDF

2. 沙盒突破
   └── iMessage 附件处理在沙盒内进行
   └── 需要额外的沙盒逃逸漏洞
   └── 沙盒逃逸漏洞本身也是宝贵的零日资源

3. 内核提权
   └── 逃逸沙盒后仍无 root 权限
   └── 需要额外的内核漏洞
   └── 需要绕过 PAC、KTRR、PPL 等缓解机制

4. 反取证
   └── 需要自动清除攻击痕迹
   └── 删除恶意 iMessage 记录
   └── 隐藏恶意进程和文件

5. 稳定性
   └── 整个攻击链必须在真实设备上稳定运行
   └── 不同设备型号和 iOS 版本都需要兼容
   └── 崩溃意味着攻击失败和目标警觉
```

## 十、Apple 的回应：从补丁到系统性防御

### 10.1 紧急补丁

Apple 在 FORCEDENTRY 被发现后迅速发布了修复：

- **iOS 14.8**（2021 年 9 月 13 日）：修复 CVE-2021-30860
- 修复方式：增强 CoreGraphics JBIG2 解码器的输入验证

### 10.2 从补丁到系统性思维的转变

FORCEDENTRY 对 Apple 的冲击不仅在于一个漏洞，而在于它暴露了一个系统性的问题：

```
Apple 安全思维转变

修补模式（传统）
┌──────────────────────────────────────────────┐
│ 发现漏洞 → 分析 → 修补 → 发布更新            │
│                                               │
│ 问题：                                        │
│ • 攻击者总能找到新漏洞                        │
│ • 修补速度永远追不上攻击速度                  │
│ • 被动应对，无法从根本上解决问题              │
│ • FORCEDENTRY 证明：即使所有已知缓解到位，    │
│   零点击攻击仍然可能成功                      │
└──────────────────────────────────────────────┘

系统防御模式（后 FORCEDENTRY）
┌──────────────────────────────────────────────┐
│ 减少攻击面 + 分层防御 + 用户选择              │
│                                               │
│ 策略：                                        │
│ • 锁定模式：为高风险用户提供精简版 iOS        │
│ • 攻击面缩减：禁用最复杂的组件                │
│ • 爆炸物检测：iMessage 中的 CSAM 检测         │
│ • 快速补丁：加速安全更新发布                  │
│ • 硬件安全：强化 PAC、PPL 等硬件级保护        │
│ • 透明度：发布威胁情报报告                    │
└──────────────────────────────────────────────┘
```

### 10.3 锁定模式的诞生

锁定模式（Lockdown Mode）是 Apple 对 FORCEDENTRY 最直接的回应，在 iOS 16（2022 年 9 月）中引入：

| 限制类别 | 具体措施 | 针对的攻击面 |
|---------|---------|-------------|
| **iMessage** | 限制附件类型，阻止链接预览 | FORCEDENTRY 类攻击 |
| **Web 浏览** | 禁用 JIT、WebGL 等复杂功能 | WebKit 零日攻击 |
| **设备连接** | 锁定时阻止 USB 数据连接 | 物理接触攻击 |
| **配置文件** | 阻止安装配置描述文件 | MDM 攻击 |
| **FaceTime** | 限制未知联系人来电 | 通信类攻击 |

### 10.4 锁定模式的局限性

FORCEDENTRY 也证明了锁定模式并非万能：

- 2023 年 BLASTPASS 成功突破了锁定模式
- 使用 CVE-2023-38606（WebKit）+ CVE-2023-36889（CoreAnimation）
- 即使限制了 iMessage 附件，WebKit 攻击面仍然存在
- 说明完全消除零点击攻击几乎不可能

- **FORCEDENTRY 后**：对 NSO Group 的部分出口许可进行审查
- **实体清单后**：与美方进行外交磋商，但未能阻止制裁
- **后续**：以色列国防部加强了对监控技术出口的内部审查机制

│           技术上最复杂的 iOS 攻击链

### 12.2 FORCEDENTRY 的多重历史意义

| 维度 | 意义 |
|------|------|
| **技术** | 代表了 iOS 利用工程的最高水平，证明了非传统攻击面的战略价值 |
| **产业** | 暴露了商业监控产业的技术深度和全球规模 |
| **人权** | 揭示了监控技术被系统性滥用于打压人权活动家的现实 |
| **政策** | 直接推动了锁定模式的诞生和国际监控技术管制讨论 |
| **法律** | 引发了 Apple 诉 NSO Group 等里程碑式诉讼 |
| **研究** | 推动了安全社区对非传统攻击面的重新审视 |

### 12.3 FORCEDENTRY 的遗产

FORCEDENTRY 的遗产超越了单一漏洞：

1. **锁定模式**：永久改变了 iOS 的安全架构方向
2. **攻击面认知**：安全社区开始系统审计以前被忽视的组件
3. **产业监管**：推动了全球监控技术出口管制框架的建设
4. **受害者赋权**：MVT 等工具使受害者能够自行检测感染
5. **透明度**：Apple 开始更公开地讨论国家级威胁

## 十三、对当代安全格局的影响

### 13.1 对 Apple 的影响

FORCEDENTRY 深刻改变了 Apple 的安全策略：

```
Apple 安全策略变化

之前                                    之后
┌────────────────────────┐    ┌────────────────────────────────┐
│ • 被动修补漏洞          │    │ • 主动减少攻击面                │
│ • 依赖通用安全缓解      │    │ • 为高风险用户提供额外保护      │
│ • 较少公开讨论威胁      │    │ • 定期发布威胁情报报告          │
│ • 标准更新周期          │    │ • 加速紧急安全更新              │
│ • 不公开讨论国家级威胁  │    │ • 公开承认并讨论国家级威胁      │
└────────────────────────┘    └────────────────────────────────┘
```

### 13.2 对其他平台的影响

FORCEDENTRY 的影响不限于 iOS：

| 平台 | 影响 |
|------|------|
| **Android** | Google 加强了 Android 的图像编解码器安全审计 |
| **WhatsApp/Signal** | 加密通信应用加强了附件处理安全 |
| **Windows** | Microsoft 重新审视了 Windows 图像处理的攻击面 |
| **Linux** | 开源社区加强了对 libtiff、libpng 等库的审计 |

### 13.3 对安全研究的影响

FORCEDENTRY 对安全研究社区产生了深远影响：

1. **攻击面重新评估**：研究者开始系统审计图像编解码器、PDF 解析器等非传统攻击面
2. **利用技术分析**：P0 的公开分析为安全社区提供了学习高级利用技术的宝贵资料
3. **防御思维转变**：从"修补所有漏洞"转向"减少攻击面 + 分层防御"
4. **工具发展**：MVT 等开源取证工具的发展使更多人能参与威胁检测

### 13.4 对普通用户的启示

虽然 FORCEDENTRY 针对的是高价值目标，但普通用户也能从中获得启示：

- **保持更新**：及时安装 iOS 更新是最基本的安全措施
- **启用锁定模式**：即使不是高风险用户，锁定模式也能提供额外保护
- **了解威胁**：了解零点击攻击的存在，提高警惕性
- **支持安全研究**：支持 Citizen Lab 等独立研究机构的工作
