## 1. 概述

### 1.1 XNU 在 iOS 安全架构中的地位

XNU（X is Not Unix）是 iOS 的核心操作系统内核，运行在 CPU 的最高特权级（EL1）。XNU 的漏洞直接导致内核代码执行，意味着攻击者获得对设备的完全控制。在典型的 iOS exploit chain 中，XNU 漏洞是最终阶段的内核提权组件。

### 1.2 XNU 架构概览

```
┌─────────────────────────────────────────────────────┐
│                    XNU Kernel                         │
├────────────────┬────────────────┬────────────────────┤
│   Mach 微内核   │    BSD 层       │     IOKit          │
│  ┌──────────┐  │  ┌──────────┐  │  ┌──────────────┐  │
│  │ IPC/Port │  │  │ Process  │  │  │ IOService    │  │
│  │ VM       │  │  │ File     │  │  │ IOUserClient │  │
│  │ Thread   │  │  │ Network  │  │  │ IOMemory     │  │
│  │ Scheduler│  │  │ Syscall  │  │  │ IODMA        │  │
│  └──────────┘  │  └──────────┘  │  └──────────────┘  │
├────────────────┴────────────────┴────────────────────┤
│              安全子系统（MAC / AMFI / Sandbox）         │
├──────────────────────────────────────────────────────┤
│              硬件抽象层（HAL / Device Tree）            │
└──────────────────────────────────────────────────────┘
```

### 1.3 清单编制方法

本清单基于以下来源编制：
- XNU 开源代码库（opensource.apple.com）
- Apple 安全更新公告（2018-2026）
- CVE 数据库中的 XNU/内核相关条目
- Google Project Zero 的内核漏洞报告
- 越狱社区（palera1n、Dopamine、checkra1n）的公开研究
- Pwn2Own 竞赛中的内核漏洞
- 内核安全会议论文（Black Hat、DEF CON、OffensiveCon）

### 1.4 风险等级定义

| 等级 | 定义 | 典型特征 |
|------|------|----------|
| **P0 - 严重** | 内核任意代码执行 | 直接控制内核，完全设备控制 |
| **P1 - 高危** | 内核信息泄露或受限代码执行 | 可获取内核地址或受限写入 |
| **P2 - 中危** | DoS 或受限信息泄露 | 内核崩溃或有限数据泄露 |
| **P3 - 低危** | 低风险信息泄露或配置问题 | 影响有限 |

### 2.1 组件概述

| 属性 | 值 |
|------|-----|
| **风险等级** | **P0 - 严重** |

| **利用影响力** | 内核代码执行、沙箱逃逸 |

### 2.2 子组件清单

#### 2.2.1 Mach Port 管理

| 属性 | 值 |
|------|-----|
| **风险等级** | P0 |
| **漏洞类型** | UAF、引用计数错误、竞态条件 |
| **攻击难度** | 中-高 |
| **历史 CVE** | CVE-2021-30761、CVE-2022-26735、CVE-2023-41990 等 |

**攻击面特征**：
- Mach port 是 iOS IPC 的核心机制
- Port 的引用计数管理复杂，容易产生 UAF
- 获得高权限服务的 port 发送权等同于获得该服务的调用能力
- Task port 泄露可直接导致沙箱逃逸

**已知漏洞模式**：
- `ipc_port_release_send` 中的竞态条件
- `ipc_object_copyin` 的权限验证缺陷
- `mach_port_mod_refs` 的引用计数溢出
- Port set 操作中的 UAF

**利用原语**：
- 获得内核 task port → 任意内核读写
- 获得高权限服务 port → 调用服务功能
- Port UAF → 内核堆控制 → 代码执行

- 消息_rights_的传递和验证

**已知漏洞模式**：
- OOL 内存描述符的引用计数错误
- 消息接收时的缓冲区管理
- `mach_msg_overwrite` 的目标缓冲区验证

## 4. IOKit 驱动框架

### 4.1 组件概述

| 属性 | 值 |
|------|-----|
| **风险等级** | **P0 - 严重** |
| **攻击向量** | 本地（IOUserClient 系统调用） |
| **历史 CVE 数量** | 80+ |
| **利用影响力** | 内核代码执行（直接） |

### 4.2 为什么 IOKit 是最高风险组件

- **直接内核执行**：IOKit 驱动运行在内核态，漏洞直接导致内核代码执行
- **广泛的攻击面**：每个硬件设备都有对应的 IOKit 驱动
- **用户可达**：用户空间可通过 `IOServiceOpen` 打开任意 `IOUserClient`
- **C++ 复杂性**：嵌入式 C++ 的虚函数表和对象生命周期管理

### 4.3 子组件清单

#### 4.3.1 IOUserClient 框架

| 属性 | 值 |
|------|-----|
| **风险等级** | P0 |
| **漏洞类型** | UAF、类型混淆、vtable 劫持 |
| **攻击难度** | 中-高 |

**攻击面特征**：
- `IOUserClient` 是用户空间与内核驱动的标准接口
- `externalMethod` 分发函数处理用户请求
- 对象的生命周期由引用计数管理

**已知漏洞模式**：
- `IOServiceClose` 与正在进行的 `externalMethod` 调用的竞态
- `IOUserClient` 子类的 `initWithTask` 参数验证
- `clientClose` / `stop` / `free` 的调用顺序
- vtable 指针的 UAF 劫持

**利用技术**：
```
1. 打开 IOUserClient
2. 触发竞态使对象被释放（UAF）
3. 重分配内存为伪造对象（控制 vtable）
4. 调用虚函数 → 劫持控制流 → 内核代码执行
```

## 37. 攻击面优先级排序

### 37.1 内核提权研究优先级

```
优先级 1（最高 ROI）：
├── IOKit IOUserClient      — 漏洞密度最高，直接内核执行
│   ├── IOMobileFramebuffer — 不需要特殊权限
│   ├── IOSurface           — 堆控制工具
│   └── AppleJPEGDriver     — TOCTOU 模式
├── Mach Port 管理          — UAF 模式成熟
└── XPC 服务               — 沙箱逃逸关键

优先级 2：
├── VM Map / Object         — 竞态条件丰富
├── VFS / Vnode             — 越狱核心技术
├── AMFI / Entitlement      — 代码签名绕过
└── GPU 驱动（AGX）         — 新攻击面

优先级 3：
├── 网络协议栈              — 远程可达但难度高
├── BSD 层                  — 传统目标
└── 蓝牙/Wi-Fi 驱动         — 远程但逆向困难
```

### 37.2 越狱工具常用组件

```
经典越狱路径：
1. WebKit RCE → 沙箱内代码执行
2. XPC/Mach Port → 沙箱逃逸
3. IOMobileFramebuffer / IOSurface → 内核提权
4. AMFI 绕过 → 代码签名自由

现代越狱路径（PAC 设备）：
1. WebKit RCE → 沙箱内代码执行
2. XPC 漏洞 → 沙箱逃逸
3. 竞态条件漏洞 → 内核提权
4. PAC 绕过 → 代码执行
```

### 37.3 新兴攻击面

```
高关注：
├── kalloc_type 绕过        — 类型隔离是新挑战
├── PPL 绕过               — 页表保护是终极目标
├── Neural Engine 驱动      — 新硬件新攻击面
└── SPTM / TXM             — 新的信任域

中关注：
├── USB-C 驱动             — 新接口新攻击面
├── 卫星通信驱动            — 新通信方式
└── Vision Pro 相关驱动     — 空间计算新组件
```

## 38. 研究策略建议

### 38.1 新手入门路径

1. **从开源 XNU 开始**：阅读 XNU 源码，理解 Mach/BSD/IOKit 架构
2. **分析已知 CVE**：复现和理解已公开的内核漏洞
3. **选择 IOKit 驱动**：IOUserClient 是最直接的攻击面
4. **学习竞态条件**：竞态条件是内核漏洞的主要类型
5. **使用内核模糊测试**：对 IOUserClient 进行模糊测试

### 38.2 中级研究者策略

1. **深入研究 Mach IPC**：Port 管理是核心攻击面
2. **VM 子系统研究**：VM 竞态条件是高价值目标
3. **补丁分析**：跟踪每个内核安全更新
4. **变体分析**：从一个 CVE 寻找同类漏洞
5. **开发自动化工具**：符号执行和模糊测试结合

### 38.3 高级研究者策略

1. **PAC 绕过研究**：指针认证是主要障碍
2. **PPL 绕过研究**：页表保护是终极目标
3. **新硬件攻击面**：Neural Engine、SPTM/TXM
4. **远程内核攻击**：网络栈和无线驱动
5. **完整 Exploit Chain**：从沙箱到内核的完整路径

### 38.4 工具推荐

| 工具 | 用途 | 适用组件 |
|------|------|---------|
| **IDA Pro / Ghidra** | 内核逆向分析 | 所有闭源组件 |
| **Frida** | 内核动态插桩 | 运行时分析 |
| **kFuzzer** | 内核模糊测试 | IOUserClient |
| **IOKit fuzzing** | IOKit 接口测试 | 所有驱动 |
| **Mach IPC fuzzing** | Mach 消息测试 | Mach 子系统 |
| **XNU 源码** | 代码审计 | 开源部分 |
