## 1. 高风险人群的定义与分类

### 1.1 什么是高风险人群

在移动安全领域，高风险人群（High-Risk Users）指的是因为其职业、身份、行为或所处环境，而面临比一般用户更高级别网络威胁的个体。这些威胁通常来自国家级攻击者（Nation-State Actors）、商业间谍软件供应商（如 NSO Group、Circus Group 等）的客户端，或组织化的高级持续性威胁（APT）团队。

高风险人群面临的核心特征包括：

- **定向攻击**：攻击者明确知道目标是谁，并愿意投入高成本进行定向攻击
- **零日漏洞利用**：攻击者使用未知漏洞或零日漏洞，绕过常规安全防线
- **零点击攻击**：无需用户交互即可完成的攻击，如 iMessage 远程代码执行
- **持续监控意图**：目标不仅是窃取数据，还包括实时监控通信、位置和活动

### 1.2 高风险人群的分类

#### 1.2.1 新闻工作者与记者

记者是商业间谍软件最常见的目标群体之一。他们调查敏感话题（腐败、人权、环境问题），与线人和消息来源通信，这些行为使他们成为监控软件的优先目标。

威胁场景：
- 通过 iMessage 或 WhatsApp 发送的零点击漏洞载荷
- 伪装成新闻线索的钓鱼链接
- 针对新闻编辑室内部通信系统的渗透
- 对线人身份的暴露企图

知名案例：
- 多名中东记者被 Pegasus 间谍软件感染
- Jamal Khashoggi 事件相关人员的手机被入侵
- 调查卡特尔犯罪的墨西哥记者遭到持续监控

#### 1.2.2 人权活动人士与社会运动参与者

人权活动人士、社会运动组织者和公民社会工作者经常与政府或强大利益集团对立。他们面临的威胁包括：

- 政府资助的间谍软件攻击
- 通信内容被截获用于打压
- 位置信息被用于物理追踪和逮捕
- 社交网络和联系人被映射

知名案例：
- 沙特活动人士 Loujain al-Hathloul 等人被监控
- 西班牙加泰罗尼亚独立运动成员通过 Pegasus 被监控
- 印度活动人士使用 WhatsApp 时被针对性攻击

#### 1.2.3 律师与法律工作者

处理敏感案件的律师，特别是涉及国家安全、人权诉讼或高价值商业纠纷的律师，可能成为监控目标。

威胁场景：
- 律师-客户特权通信被截获
- 案件策略和证据被提前获取
- 法庭文件提交前的信息泄露
- 与海外同事的通信被监控

#### 1.2.4 政府官员与外交人员

高级政府官员、外交官和军事人员面临来自其他国家情报机构的持续威胁。

威胁场景：
- 国家级 APT 团队的定向攻击
- 外交通信的截获
- 会议和谈判信息的提前获取
- 通过供应链攻击植入后门

#### 1.2.5 企业高管与关键技术人员

科技公司高管、掌握商业机密的高级管理人员，以及掌握关键基础设施信息的技术人员，也可能成为目标。

威胁场景：
- 商业间谍活动
- 并购信息的提前获取
- 技术秘密和专利信息的窃取
- 通过董事会通信系统的渗透

#### 1.2.6 异见人士与政治反对派

在威权政体下，异见人士和政治反对派成员经常成为国内监控系统的目标。

威胁场景：
- 国内情报机构的定向监控
- 社交媒体活动被实时追踪
- 与海外支持者的通信被截获
- 位置信息用于物理压制

### 1.3 威胁等级评估框架

评估个人是否属于高风险人群，可以参考以下框架：

| 评估维度 | 低风险 | 中风险 | 高风险 |
|---------|--------|--------|--------|
| 职业敏感度 | 普通商业 | 媒体/法律 | 调查新闻/人权 |
| 地理环境 | 民主国家 | 混合政体 | 威权政体/冲突区 |
| 工作对象 | 一般公众 | 敏感话题 | 政府/军方/犯罪集团 |
| 通信模式 | 本地为主 | 跨境通信 | 加密通信+匿名化 |
| 已有威胁 | 无已知威胁 | 疑似监控 | 已知被针对/同行被攻击 |

当多个维度处于高风险状态时，开启锁定模式成为必要的安全措施。

## 2. 锁定模式的设计背景与目标

### 2.1 商业间谍软件威胁的升级

2021 年 Pegasus 项目（Pegasus Project）的曝光揭示了一个令人不安的现实：商业间谍软件已经发展成为一个价值数十亿美元的产业，其客户包括数十个国家的政府机构。NSO Group 的 Pegasus、Circus Group 的 Predator（前身为 CellSpy）、Candiru 的 DevilsEye 等工具，能够远程入侵 iOS 和 Android 设备，获取完整的设备访问权限。

这些间谍软件的攻击能力包括：

- **零点击入侵**：通过 iMessage、FaceTime、WhatsApp 等应用的漏洞，无需用户任何操作即可完成感染
- **内核级权限**：获取操作系统最高权限，绕过所有应用层安全机制
- **持久化驻留**：即使设备重启也能保持访问能力
- **全面数据采集**：读取加密消息、录音、拍照、获取位置、提取密码

### 2.2 Apple 的回应

2022 年 6 月，Apple 在 WWDC 2022 上宣布将在 iOS 16 中引入锁定模式（Lockdown Mode）。这是 Apple 首次为消费级设备提供针对国家级网络攻击的防护能力。

Apple 安全工程与架构高级副总裁 Ivan Kristic 表示：

> "锁定模式是一种前所未有的、可选的保护方式，适用于极少数面临最复杂数字安全威胁的用户。虽然大多数用户永远不会成为高度复杂的网络攻击的目标，但我们将与我们的用户社区一起工作，为他们提供额外的保护层。"

### 2.3 设计目标

锁定模式的设计目标可以概括为：

**目标一：缩小攻击面**

通过禁用或限制一系列复杂功能，消除间谍软件最常用的攻击向量。零点击攻击通常依赖于复杂的媒体处理、字体渲染、链接解析等功能，锁定模式通过限制这些功能来切断攻击路径。

**目标二：提供可操作的防护**

不同于需要专业技术知识的安全配置，锁定模式只需一个开关即可激活。用户不需要理解底层技术细节，就能获得显著的安全提升。

**目标三：保持基本可用性**

锁定模式并非将设备变成"砖头"。Apple 在设计时考虑了高风险用户的日常需求，确保基本通信、浏览和应用功能仍然可用，只是在安全边界上做出了取舍。

**目标四：渐进式适配**

锁定模式允许用户针对特定应用单独放宽限制（如批准特定联系人发送附件），使安全保护可以根据实际威胁动态调整。

### 2.4 锁定模式在 Apple 安全体系中的位置

Apple 的安全架构是多层防御体系：

```
┌─────────────────────────────────────────────┐
│           用户行为与安全意识                    │
├─────────────────────────────────────────────┤
│         锁定模式（极端攻击面缩减）              │
├─────────────────────────────────────────────┤
│         应用沙箱与权限控制                      │
├─────────────────────────────────────────────┤
│    PAC / MTE / W^X / ASLR（内存安全）          │
├─────────────────────────────────────────────┤
│    Secure Enclave / Secure Boot（硬件信任根）   │
├─────────────────────────────────────────────┤
│         硬件安全引擎（AES 引擎等）              │
└─────────────────────────────────────────────┘
```

锁定模式位于软件防御层的最上方，是用户可以直接控制的最后一道防线。它不替代底层安全机制，而是在这些机制之上增加额外的攻击面缩减层。

## 3. 锁定模式的技术架构

### 3.1 实现机制

锁定模式在 iOS 中通过一个系统级的配置标志（flag）实现。当用户开启锁定模式时，系统会在多个层面调整行为：

**系统配置层**

锁定模式的状态存储在系统的受保护配置区域中。一旦开启，这个状态会影响所有系统应用和许多第三方应用的行为。应用可以通过系统 API 查询锁定模式的状态，并据此调整自身功能。

```swift
// 应用可以检测锁定模式是否开启
if #available(iOS 16, *) {
    let isLockdownEnabled = ProcessInfo.processInfo
        .isLowPowerModeEnabled // 简化示意
    // 实际应用使用专门的 API 检测
}
```

**进程级限制**

系统的各个服务进程会检查锁定模式状态，并据此限制功能：

- Messages 进程：限制消息附件类型和处理方式
- WebKit 进程：禁用 JIT 编译和复杂 JavaScript 特性
- Media 服务：限制编解码器类型和媒体处理管线
- Network 服务：限制网络连接类型和协议

**沙箱策略调整**

锁定模式下，应用的沙箱策略更加严格：

- 文件访问权限进一步收紧
- 网络访问规则更加严格
- IPC（进程间通信）限制增强
- 共享资源访问受到更多约束

### 3.2 攻击面缩减矩阵

锁定模式通过以下机制缩减攻击面：

| 攻击向量 | 正常模式 | 锁定模式 | 缩减程度 |
|---------|---------|---------|---------|
| iMessage 附件 | 所有类型 | 仅基本图片/视频 | 高 |
| 网页 JIT 编译 | 启用 | 禁用 | 高 |
| 链接预览 | 启用 | 禁用 | 中 |
| 设备连接 | USB 配件 | 需解锁授权 | 中 |
| FaceTime | 所有入站 | 仅已知联系人 | 高 |
| 配置文件安装 | 允许 | 禁止 | 高 |
| 远程管理 | 允许 | 禁止 | 高 |

### 3.3 与正常模式的性能对比

锁定模式对设备性能的影响主要体现在以下方面：

**网页加载**

由于禁用了 JIT 编译，JavaScript 密集型网页的加载速度会下降。实测数据显示：

- 简单静态网页：影响 < 5%
- 中等复杂度网页：速度下降 10-20%
- JavaScript 密集型应用（如 Google Docs）：速度下降 30-50%

**消息处理**

- 文本消息：无影响
- 图片消息：无影响
- 复杂附件：无法接收（功能被禁用）

**多媒体**

- 基本拍照/录像：无影响
- 复杂媒体编辑：部分功能受限
- 第三方媒体应用：可能受影响

### 3.4 锁定模式的系统级集成

锁定模式与 iOS 的其他安全功能深度集成：

**与数据保护配合**

锁定模式不影响设备的数据加密机制。设备的文件系统加密仍然由 Secure Enclave 和用户密码保护。锁定模式的作用是在设备解锁状态下减少攻击面。

**与 App Tracking Protection 配合**

在 iOS 17+ 中，锁定模式与 App Tracking Protection 协同工作，提供更全面的网络层保护。App Tracking Protection 在 DNS 层面阻止已知跟踪器，而锁定模式在应用层面限制功能。

**与 Stolen Device Protection 配合**

iOS 17.3 引入的 Stolen Device Protection 在设备被盗时提供额外保护。锁定模式与 Stolen Device Protection 可以叠加使用，为高风险人群提供双重保护。

## 4. 谁应该开启锁定模式

### 4.1 决策框架

并非所有 iOS 用户都需要开启锁定模式。Apple 明确表示，锁定模式适用于"极少数面临最复杂数字安全威胁的用户"。以下决策框架可以帮助判断是否需要开启：

**开启锁定模式的信号**

- 收到明确的安全威胁
- 从事敏感调查工作（腐败、犯罪、人权侵犯）
- 与高价值目标（政府官员、犯罪头目）有直接通信
- 工作地区存在活跃的商业间谍软件使用记录
- 同行或同事已被确认遭到间谍软件攻击
- 设备出现可疑行为（异常发热、电池消耗、未知进程）
- 收到来自未知来源的可疑消息或链接

**可能不需要锁定模式的场景**

- 一般个人隐私保护需求（使用标准安全功能即可）
- 防范普通网络犯罪（钓鱼、身份盗窃）
- 保护商业机密但无国家级威胁
- 设备仅用于日常娱乐和社交

### 4.2 职业风险评估

#### 4.2.1 必须开启的职业

- **战地记者与冲突区报道者**：面临国家级监控和物理威胁
- **调查腐败的记者**：调查对象可能有资源使用商业间谍软件
- **人权组织负责人**：在威权政体下工作的活动人士
- **处理国家安全案件的律师**：案件涉及的情报机构可能进行监控
- **高级外交官**：驻敏感地区的使馆人员

#### 4.2.2 建议开启的职业

- **科技行业举报人**：掌握大公司敏感信息
- **环保活动人士**：调查环境污染的企业可能有监控能力
- **反腐败 NGO 工作者**：调查对象可能使用间谍软件
- **独立审计师**：审计敏感财务信息
- **政治竞选核心成员**：选举期间的间谍活动风险

#### 4.2.3 可选开启的场景

- **普通记者**：不直接调查高威胁目标
- **企业法务**：处理一般商业纠纷
- **社交媒体影响者**：面临骚扰但非国家级威胁
- **医疗工作者**：处理敏感患者信息但无定向威胁

### 4.3 情境风险评估

除了职业因素，以下情境也可能触发锁定模式的需求：

**临时高风险情境**

- 参加敏感国际会议（如联合国气候大会）
- 前往已知使用间谍软件的国家
- 在重大新闻事件发布前的保密期
- 法庭审判期间的敏感通信

**持续性高风险情境**

- 长期与受制裁实体有通信往来
- 持续报道敏感话题
- 在多个国家间频繁旅行
- 维护匿名消息来源网络

### 4.4 威胁情报参考

以下公开资源可以帮助评估个人威胁等级：

- **Citizen Lab 报告**：追踪 Pegasus 等间谍软件的使用情况
- **Access Now 数字安全热线**：为公民社会提供安全支持
- **Committee to Protect Journalists（CPJ）**：记者安全资源
- **Front Line Defenders**：人权捍卫者安全支持
- **Reporters Without Borders（RSF）**：新闻自由和安全资源

这些组织定期发布关于间谍软件使用趋势和地理分布的报告，可以帮助高风险人群了解自己是否处于威胁区域。

## 5. 锁定模式的启用流程

### 5.1 前置准备

在开启锁定模式之前，建议完成以下准备工作：

**步骤一：更新 iOS 到最新版本**

锁定模式在 iOS 16 及以上版本可用。确保设备运行最新版本的 iOS，以获得最完整的安全保护。

```
设置 → 通用 → 软件更新 → 检查更新
```

**步骤二：备份设备**

锁定模式可能影响某些应用的正常工作。在开启前备份设备，以便在需要时恢复。

```
设置 → [用户名] → iCloud → iCloud 备份 → 立即备份
```

或使用 Finder/iTunes 进行本地加密备份。

**步骤三：通知关键联系人**

锁定模式会影响消息附件和某些通信功能。提前通知经常通信的关键联系人（编辑、律师、同事），让他们了解可能出现的功能限制。

**步骤四：了解功能限制**

仔细阅读本章后续内容和第 6-9 章的功能限制详解，确保理解开启后的影响。

### 5.2 启用步骤

锁定模式的启用过程非常简单：

```
步骤 1：打开"设置"应用
步骤 2：滚动到"隐私与安全性"
步骤 3：滚动到最底部，找到"锁定模式"
步骤 4：点击"锁定模式"
步骤 5：点击"开启锁定模式"
步骤 6：系统会弹出说明对话框，解释功能限制
步骤 7：点击"开启并重启"
步骤 8：设备自动重启
步骤 9：重启后，锁定模式即生效
```

设备重启后，锁定模式立即生效。状态栏不会显示任何特殊图标，但可以在"设置 → 隐私与安全性 → 锁定模式"中确认状态。

### 5.3 通过 MDM 远程启用（企业场景）

对于企业环境中的高风险员工，IT 管理员可以通过 MDM（移动设备管理）远程启用锁定模式：

**MDM 配置**

```xml
<key>com.apple.applicationaccess.new</key>
<dict>
    <key>forceLockdownMode</key>
    <true/>
</dict>
```

**注意事项**

- MDM 强制启用的锁定模式，用户无法自行关闭
- 需要 MDM 服务器支持 iOS 16+ 的配置描述文件
- 建议先在测试设备上验证兼容性
- 需要与员工沟通功能限制的影响

**主流 MDM 支持情况**

| MDM 平台 | 支持锁定模式 | 配置方式 |
|---------|------------|---------|
| Jamf Pro | 是 | 安全负载配置 |
| Microsoft Intune | 是 | 自定义 OMA-URI |
| VMware Workspace ONE | 是 | 设备配置文件 |
| Kandji | 是 | 安全策略 |
| Mosyle | 是 | 限制配置 |

### 5.4 关闭锁定模式

如果需要关闭锁定模式：

```
步骤 1：打开"设置"应用
步骤 2：进入"隐私与安全性" → "锁定模式"
步骤 3：点击"关闭锁定模式"
步骤 4：确认关闭
```

**注意**：如果是通过 MDM 强制启用的锁定模式，用户无法自行关闭，需要联系 IT 管理员。

### 5.5 锁定模式的状态检测

**对于用户**

```swift
    return false // 简化
}
```

## 6. 功能限制详解：消息与通信

### 6.1 iMessage 限制

iMessage 是零点击攻击最常见的攻击向量之一。Pegasus 的 FORCEDENTRY 攻击就是通过 iMessage 的 PDF 渲染漏洞实现的。锁定模式对 iMessage 进行了严格限制：

**附件限制**

| 附件类型 | 正常模式 | 锁定模式 |
|---------|---------|---------|
| 照片（JPEG/HEIC） | ✅ 允许 | ✅ 允许 |
| 视频（MP4/MOV） | ✅ 允许 | ✅ 允许（基本格式） |
| 音频（M4A/AAC） | ✅ 允许 | ✅ 允许 |
| PDF 文件 | ✅ 允许 | ❌ 阻止 |
| Office 文档 | ✅ 允许 | ❌ 阻止 |
| 可执行文件 | ❌ 阻止 | ❌ 阻止 |
| 压缩包 | ✅ 允许 | ❌ 阻止 |
| 应用分享 | ✅ 允许 | ❌ 阻止 |
| 数字触控板/手绘 | ✅ 允许 | ❌ 阻止 |
| 位置分享 | ✅ 允许 | ❌ 阻止 |

**链接预览**

正常模式下，iMessage 会自动加载消息中链接的预览信息（标题、缩略图）。这个过程涉及 HTTP 请求和 HTML 解析，可能被利用进行攻击或追踪。

锁定模式下：
- 链接预览被禁用
- 消息中的 URL 显示为纯文本
- 不会自动加载任何外部资源

**影响评估**

- 日常文本通信：无影响
- 分享照片和视频：基本不受影响
- 工作文档传输：受重大影响（PDF、Office 文件被阻止）
- 复杂协作：受影响（手绘、位置分享不可用）

### 6.2 第三方消息应用

锁定模式主要影响 Apple 原生应用。第三方消息应用（如 Signal、WhatsApp、Telegram）的行为取决于应用自身的实现：

**Signal**

- Signal 的端到端加密通信不受锁定模式影响
- Signal 的附件处理可能受到系统级限制
- Signal Call 可能受到与 FaceTime 类似的限制

**WhatsApp**

- 基本消息功能正常
- 媒体附件可能受到系统级限制
- WhatsApp Call 功能正常

**Telegram**

- 基本消息功能正常
- Telegram 的丰富媒体支持可能部分受限
- 机器人和小程序功能可能受限

### 6.3 FaceTime

锁定模式对 FaceTime 的限制：

- **入站 FaceTime 呼叫**：仅接受已知联系人的呼叫。未知号码的 FaceTime 呼叫被自动拒绝
- **FaceTime 链接**：创建和加入 FaceTime 链接可能被限制
- **SharePlay**：被禁用
- **屏幕共享**：被禁用

**安全逻辑**

FaceTime 的零点击攻击向量包括：
- 通过恶意构造的呼叫信令触发漏洞
- 利用呼叫建立过程中的媒体协商漏洞
- 通过 SharePlay 的复杂媒体共享功能

限制为仅已知联系人可以大幅降低这些攻击的风险。

### 6.4 短信（SMS）与彩信（MMS）

锁定模式对传统短信和彩信的影响：

- **纯文本短信**：不受影响
- **彩信（MMS）**：
  - 图片彩信：基本格式允许
  - 视频彩信：基本格式允许
  - 复杂附件：被阻止
  - 链接预览：被禁用

**安全注意**

SMS 本身不是安全通信方式。短信内容不加密，可被运营商和中间人读取。高风险人群应优先使用 Signal 等端到端加密通信工具。

### 6.5 邮件

锁定模式对邮件应用的影响：

- **纯文本邮件**：不受影响
- **HTML 邮件**：渲染可能受限
- **远程图片加载**：默认禁用（与正常模式的"保护邮件隐私"一致）
- **邮件附件**：复杂附件类型可能被限制打开
- **邮件中的链接**：预览被禁用

**建议**

高风险人群应使用 ProtonMail、Tutanota 等端到端加密邮件服务，配合锁定模式获得更好的保护。

### 6.6 通信功能的适配策略

对于高风险人群，开启锁定模式后的通信适配策略：

**策略一：建立安全通信协议**

与关键联系人约定：
- 使用 Signal 作为主要通信工具
- 重要文档通过安全文件传输渠道发送
- 紧急情况使用电话呼叫
- 敏感信息使用阅后即焚功能

**策略二：提前共享附件**

如果需要在锁定模式下共享文档：
- 将文档上传到加密云存储
- 通过安全链接分享（而非直接附件）
- 接收方需要在非锁定模式设备上查看

**策略三：建立通信白名单**

锁定模式下，只有已知联系人可以发起通信。确保：
- 所有重要联系人已保存到通讯录
- 新联系人通过其他渠道验证后再加入
- 定期清理不再需要的联系人

## 7. 功能限制详解：网页浏览与网络

### 7.1 WebKit 限制

锁定模式对 Safari 和所有使用 WebKit 引擎的第三方浏览器施加了严格限制：

**JIT 编译禁用**

JavaScript JIT（Just-In-Time）编译是提升 JavaScript 执行速度的关键技术，但也是浏览器攻击中最常见的漏洞利用目标。JIT 编译器需要将可执行代码写入内存并执行，这与 W^X（Write XOR Execute）安全原则冲突，创造了攻击面。

锁定模式下：
- JIT 编译被完全禁用
- JavaScript 使用解释器模式执行
- 性能影响：JavaScript 密集型网页速度下降 30-50%

**受影响的网页应用**

| 应用类型 | 影响程度 | 说明 |
|---------|---------|------|
| 静态新闻网站 | 无影响 | 基本 HTML/CSS 渲染正常 |
| 搜索引擎 | 轻微影响 | 基本搜索功能正常 |
| 社交媒体 | 中等影响 | 动态加载和交互变慢 |
| Google Docs/Sheets | 重大影响 | 复杂编辑功能可能不可用 |
| Figma/Canva | 重大影响 | 设计工具依赖 JIT 性能 |
| 在线游戏 | 重大影响 | 大多数游戏无法正常运行 |
| 网银 | 轻微影响 | 基本功能正常 |

**Web API 限制**

锁定模式还限制了某些 Web API 的使用：

- **WebGL**：可能被限制或禁用（3D 图形渲染）
- **WebAssembly**：可能受限（高性能计算）
- **Service Workers**：可能被限制（离线缓存）
- **Web Notifications**：可能被限制
- **Geolocation API**：可能被限制
- **Web Bluetooth/USB**：被禁用

### 7.2 链接处理

锁定模式改变了链接的处理方式：

**链接预览禁用**

正常模式下，iOS 在许多场景中会自动加载链接预览：
- iMessage 中的链接
- Safari 的阅读列表
-  Spotlight 搜索建议
- 邮件中的链接

锁定模式下，这些预览功能被禁用。链接不会被自动访问，减少了通过链接进行追踪或攻击的风险。

**通用链接（Universal Links）限制**

通用链接允许在应用中直接打开网站内容（如在 Twitter 应用中打开 Twitter 链接）。锁定模式下，某些通用链接可能被限制，强制在浏览器中打开。

### 7.3 网络层保护

锁定模式与 iOS 的网络层安全功能协同工作：

**ICloud 专用中继（iCloud Private Relay）**

如果用户订阅了 iCloud+，iCloud 专用中继继续正常工作。它通过两个中继层保护用户的浏览隐私：
- 第一个中继分配匿名 IP 地址
- 第二个中继解密目标域名

**DNS  over HTTPS（DoH）**

锁定模式不影响 DoH 的使用。加密 DNS 查询继续保护用户的域名解析隐私。

**网络追踪保护**

Safari 的智能追踪防护（ITP）在锁定模式下继续工作，并且在某些方面更加严格：
- 跨站追踪器阻止更加激进
- Cookie 隔离更加严格
- 指纹保护增强

### 7.4 第三方浏览器

锁定模式对所有浏览器生效，不仅限于 Safari：

- **Chrome for iOS**：使用 WebKit 引擎，受同样限制
- **Firefox for iOS**：使用 WebKit 引擎，受同样限制
- **Brave for iOS**：使用 WebKit 引擎，受同样限制
- **Edge for iOS**：使用 WebKit 引擎，受同样限制

所有第三方浏览器在 iOS 上都必须使用 WebKit 引擎，因此锁定模式的限制对所有浏览器一致适用。

### 7.5 网页浏览的适配策略

**策略一：使用精简版网页**

许多网站提供精简版或纯文本版：
- Wikipedia 纯文本版
- 新闻网站的打印版
- Google 的 HTML 基本版

**策略二：使用阅读模式**

Safari 的阅读模式可以提取网页的主要内容，减少复杂的 JavaScript 和样式：
- 打开网页后点击地址栏的阅读模式按钮
- 阅读模式自动简化页面内容
- 减少潜在的攻击面

**策略三：使用专用应用**

对于常用的服务，使用专用应用通常比网页版更高效：
- Twitter/X 应用
- Reddit 应用
- 新闻聚合应用

专用应用不依赖 WebKit，因此不受 JIT 禁用的影响。

## 9. 功能限制详解：设备连接与共享

### 9.1 USB 配件限制

锁定模式增强了 USB 连接的安全性：

- **恶意充电线**：如 O.MG Cable，内置攻击芯片

- 设备锁定时，USB 配件连接被拒绝

实际上，iOS 从 iOS 11.4.1 开始就有一个"USB 限制模式"：如果设备超过 1 小时未解锁，USB 数据连接被禁用。锁定模式将这个限制更加严格化。

**安全逻辑**

AirDrop 使用蓝牙和 Wi-Fi 直连进行文件传输。恶意攻击者可以在近距离内发送 AirDrop 请求，可能包含恶意内容或用于追踪设备。

### 9.5 外部显示器与投影

### 9.6 蓝牙设备

## 10. 锁定模式对零点击攻击的防御效果

### 10.1 零点击攻击概述

零点击攻击（Zero-Click Attack）是指不需要用户任何交互即可完成的攻击。攻击者无需诱骗用户点击链接、打开附件或安装应用，就能远程入侵设备。

零点击攻击的特点：

- **完全远程**：攻击可以在世界任何地方发起
- **无用户感知**：受害者完全不知道攻击正在发生
- **高成功率**：利用已知漏洞，攻击可靠性高
- **高成本**：每个漏洞利用通常需要数十万到数百万美元

### 10.2 iMessage 零点击攻击

iMessage 是 iOS 零点击攻击最常见的攻击向量：

**FORCEDENTRY（2021）**

- **攻击向量**：iMessage 的 PDF 渲染引擎
- **漏洞类型**：整数溢出导致堆缓冲区溢出
- **攻击过程**：
  1. 攻击者通过 iMessage 发送恶意构造的 GIF 文件
  2. GIF 文件被 CoreGraphics 框架解析
  3. 恶意数据触发整数溢出
  4. 溢出导致堆缓冲区溢出
  5. 攻击者代码获得执行权限
- **用户交互**：无（消息自动处理）
- **锁定模式防御**：✅ 有效（限制 GIF 和复杂媒体处理）

**BlastDoor 绕过攻击**

BlastDoor 是 iOS 14 引入的 iMessage 沙箱服务，用于隔离和检查入站消息。多个攻击已经绕过了 BlastDoor：

- **CVE-2022-22674**：通过恶意 HTML 绕过 BlastDoor
- **CVE-2022-26735**：通过 OOB（Out-of-Bounds）写入绕过
- **CVE-2023-32409**：通过 JavaScript 引擎漏洞绕过

锁定模式防御：✅ 有效（限制消息类型和复杂内容处理）

### 10.3 WebKit 零点击攻击

WebKit 是 iOS 上所有浏览器的引擎，也是零点击攻击的重要目标：

**CVE-2021-30860（FORCEDENTRY 变体）**

- **攻击向量**：CoreMedia 框架
- **漏洞类型**：整数溢出
- **利用场景**：通过网页或 iMessage 触发

**CVE-2022-22620**

- **攻击向量**：WebKit 的 Universal XSS
- **漏洞类型**：逻辑错误
- **利用场景**：通过恶意网页触发

锁定模式防御：✅ 有效（禁用 JIT 编译，减少攻击面）

### 10.4 内核零点击攻击

最高级别的零点击攻击直接针对 iOS 内核：

**CVE-2023-32434**

- **攻击向量**：AppleJPEGDriver
- **漏洞类型**：堆损坏
- **影响**：内核代码执行
- **利用链**：通常作为完整攻击链的最后一步

锁定模式防御：⚠️ 部分有效（减少初始攻击向量，但内核漏洞本身不受锁定模式直接影响）

### 10.5 防御效果评估

锁定模式对零点击攻击的防御效果：

| 攻击类型 | 正常模式风险 | 锁定模式风险 | 防御效果 |
|---------|------------|------------|---------|
| iMessage 零点击 | 高 | 极低 | ★★★★★ |
| WebKit 零点击 | 中 | 低 | ★★★★☆ |
| FaceTime 零点击 | 中 | 极低 | ★★★★★ |
| 邮件零点击 | 低 | 极低 | ★★★★☆ |
| 内核零点击 | 低 | 低 | ★★☆☆☆ |

**关键结论**

锁定模式通过缩减攻击面，有效地消除了大多数零点击攻击向量。虽然不能提供 100% 的保护（特别是针对内核漏洞），但显著提高了攻击者的成本和难度。

对于商业间谍软件如 Pegasus，锁定模式可能使其现有攻击工具失效，迫使攻击者开发新的漏洞利用，这需要额外的时间和资源。

## 11. 锁定模式的局限性与盲区

### 11.1 不能防御的攻击类型

锁定模式虽然强大，但并非万能。以下攻击类型不受锁定模式的直接影响：

**社会工程学攻击**

锁定模式无法防止用户被欺骗：
- 钓鱼攻击（如果用户主动点击链接）
- 身份冒充（攻击者伪装成可信联系人）
- 电话诈骗

**物理攻击**

如果攻击者物理接触设备：
- 设备被偷窥（ Shoulder Surfing）
- 设备被安装硬件后门
- 设备被连接到恶意计算机

**供应链攻击**

锁定模式无法防止：
- 恶意应用通过 App Store 分发
- 被篡改的 iOS 更新
- 被入侵的 iCloud 账户

**零日内核漏洞**

如果攻击者拥有 iOS 内核零日漏洞：
- 锁定模式不能阻止内核级攻击
- 内核漏洞可以绕过所有用户级限制

### 11.2 锁定模式的可用性代价

锁定模式的安全提升是以可用性为代价的：

**生产力影响**

- 无法直接接收和查看 PDF 附件
- 网页应用性能下降
- 某些协作功能受限
- 文档处理能力降低

**通信影响**

- 无法接收未知来源的消息
- 附件类型受限
- 某些通信功能不可用

**工作流影响**

- 需要调整工作流程
- 可能需要额外的设备或工具
- 与同事的协作方式需要改变

### 11.3 锁定模式不是银弹

**威胁模型匹配**

锁定模式适用于特定的威胁模型：
- ✅ 针对商业间谍软件（Pegasus、Predator 等）
- ✅ 针对零点击远程攻击
- ✅ 针对消息和网络攻击向量
- ❌ 不针对物理攻击
- ❌ 不针对社会工程学
- ❌ 不针对供应链攻击
- ❌ 不针对内部威胁

**综合安全策略**

锁定模式应该作为综合安全策略的一部分，而不是唯一的安全措施：

```
综合安全策略
├── 锁定模式（技术防护）
├── 安全意识培训（人的因素）
├── 端到端加密通信（通信安全）
├── 定期安全审计（持续监控）
├── 事件响应计划（应急准备）
└── 物理安全措施（设备保护）
```

### 11.4 锁定模式的误报与漏报

**误报（False Positive）**

某些用户可能不必要地开启了锁定模式：
- 威胁评估不准确
- 功能限制影响工作和生活
- 安全焦虑过度

**漏报（False Negative）**

某些高风险用户可能没有开启锁定模式：
- 不了解锁定模式的存在
- 不了解自身面临的威胁
- 担心功能限制

### 11.5 锁定模式的持续性挑战

**持续更新**

攻击者会不断开发新的攻击技术。锁定模式需要随着威胁的演变而更新：
- Apple 需要持续调整锁定模式的限制
- 新功能可能引入新的攻击面
- 攻击者会寻找锁定模式的绕过方法

**兼容性维护**

随着 iOS 的发展，锁定模式需要与新技术兼容：
- 新的 iOS 功能需要适配锁定模式
- 第三方应用需要支持锁定模式
- 企业应用需要测试兼容性

## 12. 高风险人群的日常安全适配

### 12.1 通信安全适配

**建立安全通信协议**

高风险人群应该与关键联系人建立明确的安全通信协议：

**协议一：分级通信**

| 信息级别 | 通信方式 | 工具 |
|---------|---------|------|
| 一般信息 | 普通消息 | iMessage/WhatsApp |
| 敏感信息 | 加密消息 | Signal |
| 高度敏感 | 阅后即焚 | Signal 消失消息 |
| 紧急信息 | 电话呼叫 | Signal Call |

**协议二：验证机制**

建立联系人验证机制：
- 新联系人通过视频通话验证身份
- 敏感信息使用预设暗号
- 定期更换通信工具

**协议三：应急通信**

准备应急通信方案：
- 备用通信工具
- 紧急联系人列表
- 安全会面地点

### 12.2 工作流程适配

**文档处理工作流**

对于需要处理文档的高风险人群：

```
工作流一：安全文档处理
1. 发送方将文档转换为图片格式
2. 通过 Signal 发送图片
3. 接收方在锁定模式设备上查看
4. 需要编辑时，在专用设备上处理

工作流二：云文档协作
1. 使用 Proton Drive 或 Tresorit 存储文档
2. 通过加密链接共享
3. 使用纯文本格式减少格式依赖
4. 定期同步和备份
```

**会议与协作工作流**

```
工作流一：安全会议
1. 使用 Signal Group Call 进行加密通话
2. 会议材料提前通过安全渠道分发
3. 会议记录使用纯文本格式
4. 敏感决策通过安全渠道确认

工作流二：跨组织协作
1. 建立安全通信群组
2. 使用端到端加密协作工具
3. 定期审查参与者权限
4. 建立信息分级制度
```

### 12.3 设备管理适配

**多设备策略**

高风险人群可能需要使用多设备策略：

**方案一：双设备方案**

- 设备 A（锁定模式）：日常通信、敏感信息
- 设备 B（正常模式）：文档处理、网页应用
- 两台设备物理隔离，不共享 iCloud 账户

**方案二：三设备方案**

- 设备 A（锁定模式）：最高安全级别通信
- 设备 B（正常模式）：日常工作
- 设备 C（专用设备）：敏感文档处理

**设备同步注意事项**

- 不在设备间同步敏感信息
- 使用不同的 Apple ID
- 不启用 iCloud 备份（或仅备份非敏感设备）

### 12.4 信息安全适配

**信息分级制度**

建立信息分级制度：

| 级别 | 描述 | 处理方式 |
|------|------|---------|
| 公开 | 可公开的信息 | 普通处理 |
| 内部 | 仅限组织内部 | 加密存储 |
| 敏感 | 泄露会造成损害 | 端到端加密 |
| 机密 | 泄露会造成严重损害 | 最小化传播 |
| 绝密 | 泄露会造成灾难性损害 | 物理隔离 |

**信息最小化原则**

- 只保留必要的信息
- 定期清理不再需要的数据
- 使用阅后即焚功能
- 避免在设备上存储敏感信息

### 12.5 应急响应适配

**安全事件检查清单**

如果怀疑设备被入侵：

```
□ 1. 断开网络连接（飞行模式）
□ 2. 关闭设备电源
□ 3. 使用备用通信设备联系安全团队
□ 4. 不要尝试自行调查
□ 5. 记录可疑活动的时间线
□ 6. 保留设备原始状态（不要重置）
□ 7. 联系专业安全机构（如 Citizen Lab、Access Now）
```

**备用通信准备**

- 准备备用手机（预装 Signal）
- 存储紧急联系人信息（物理备份）
- 建立安全会面地点
- 准备现金和身份证明文件

## 13. 企业环境中的锁定模式部署

### 13.1 企业部署场景

在企业环境中，锁定模式的部署通常涉及以下场景：

**场景一：高管保护**

为 CEO、CFO 等高管的设备启用锁定模式：
- 保护战略决策信息
- 防止并购信息泄露
- 保护董事会通信

**场景二：敏感项目组**

为参与敏感项目的团队成员启用锁定模式：
- 研发项目保护
- 法律案件团队
- 并购团队

**场景三：海外派遣人员**

为派往高风险地区的人员启用锁定模式：
- 驻冲突区员工
- 驻高监控国家人员
- 参加国际会议的代表

### 13.2 MDM 部署策略

**策略一：强制启用**

通过 MDM 强制为特定设备组启用锁定模式：

```xml
<key>com.apple.applicationaccess.new</key>
<dict>
    <key>forceLockdownMode</key>
    <true/>
    <key>payloadDisplayName</key>
    <string>Lockdown Mode Enforcement</string>
</dict>
```

**优点**：
- 确保所有目标设备都启用锁定模式
- 用户无法自行关闭
- 集中管理

**缺点**：
- 用户可能遇到功能限制问题
- 需要充分的用户培训
- 可能需要例外处理机制

**策略二：建议启用**

通过 MDM 推送通知，建议用户启用锁定模式：

```xml
<key>com.apple.managedconfiguration.profiled</key>
<dict>
    <key>lockdownModeRecommendation</key>
    <true/>
</dict>
```

**优点**：
- 用户可以选择是否启用
- 减少功能限制带来的问题
- 提高用户接受度

**缺点**：
- 无法确保所有目标设备都启用
- 依赖用户的安全意识

### 13.3 兼容性测试

在大规模部署锁定模式之前，必须进行兼容性测试：

**测试清单**


## 14. 真实案例分析：锁定模式的实战价值

### 14.1 案例一：中东记者的保护

**背景**

一名调查中东腐败问题的记者，其同事已被确认遭到 Pegasus 间谍软件攻击。该记者收到多个可疑的 iMessage 消息，来源不明。

**威胁评估**

- 威胁级别：高
- 攻击向量：iMessage 零点击攻击
- 攻击者能力：国家级（可能使用 Pegasus）

**应对措施**

1. 立即启用锁定模式
2. 通知所有消息来源和关键联系人
3. 切换到 Signal 作为主要通信工具
4. 停止在设备上存储敏感文件

**结果**

- 启用锁定模式后，可疑消息停止
- 记者继续使用 iPhone 进行日常工作
- 敏感通信通过 Signal 进行
- 未发生进一步的安全事件

**经验教训**

- 锁定模式有效阻止了已知的 iMessage 攻击向量
- 提前建立安全通信协议很重要
- 记者需要了解功能限制并做好准备

### 14.2 案例二：人权组织的批量保护

**背景**

一家人权组织在多个国家有工作人员，其中两名工作人员的设备出现可疑行为（异常电池消耗、未知进程）。

**威胁评估**

- 威胁级别：高
- 受影响人员：2 名现场工作人员
- 潜在风险：所有工作人员

**应对措施**

1. 为所有高风险工作人员（15 人）启用锁定模式
2. 通过 MDM 统一配置
3. 进行全员安全培训
4. 建立安全通信协议
5. 与 Citizen Lab 合作进行设备检测

**结果**

- Citizen Lab 确认 2 名工作人员的设备曾被 Pegasus 感染
- 启用锁定模式后，未发生新的感染
- 组织继续正常运作
- 敏感信息保护得到加强

**经验教训**

- 批量部署锁定模式需要 MDM 支持
- 用户培训是成功部署的关键
- 与专业安全机构合作很有价值

### 14.3 案例三：律师事务所的敏感案件保护

**背景**

一家律师事务所正在处理一起涉及国家安全的高调案件。合伙人们担心通信被监控。

**威胁评估**

- 威胁级别：中高
- 攻击向量：可能来自多个方向
- 敏感信息：案件策略、客户通信、证据

**应对措施**

1. 为参与案件的律师启用锁定模式
2. 建立安全文档处理流程
3. 使用专用安全设备处理最敏感信息
4. 与客户建立安全通信渠道

**结果**

- 案件信息未泄露
- 律师能够继续正常工作（虽有功能限制）
- 客户对安全措施表示满意
- 案件成功完成

**经验教训**

- 锁定模式适用于法律保护场景
- 需要与客户沟通功能限制
- 专用设备可以补充锁定模式的限制

### 14.4 案例四：企业高管的并购保护

**背景**

一家科技公司即将宣布一项重大收购。高管团队担心信息泄露导致股价波动或交易失败。

**威胁评估**

- 威胁级别：中
- 威胁来源：竞争对手、媒体、市场投机者
- 敏感信息：收购目标、价格、时间表

**应对措施**

1. 为参与并购的高管启用锁定模式
2. 使用加密通信工具
3. 限制信息传播范围
4. 建立信息泄露监控

**结果**

- 收购信息在宣布前未泄露
- 交易成功完成
- 高管团队适应锁定模式的限制

**经验教训**

- 锁定模式可以用于临时性的高风险场景
- 商业场景中的应用需要平衡安全和效率
- 信息最小化原则很重要

从以上案例中可以总结出以下共同点：

1. 准确的威胁评估
2. 及时启用锁定模式
3. 充分的用户培训
4. 配套的安全措施
5. 专业机构的支持

**常见挑战**

1. 功能限制带来的不便
2. 与外部人员的沟通
3. 工作流程的调整
4. 持续的安全意识维护

## 15. 锁定模式与其他安全措施的协同

### 15.1 与端到端加密通信的协同

锁定模式应该与端到端加密通信工具配合使用：

**Signal**

- Signal 的端到端加密不受锁定模式影响
- Signal 的消息在传输过程中已经加密
- 锁定模式保护 Signal 应用本身不被攻击

**推荐配置**

```
锁定模式 + Signal 配置：
1. 启用锁定模式
2. 安装 Signal
3. 启用 Signal 的"消失消息"功能
4. 使用 Signal 作为主要通信工具
5. 定期验证联系人安全码
```

### 15.2 与密码管理器的协同

锁定模式不影响密码管理器的使用：

**1Password / Bitwarden / iCloud 钥匙串**

- 密码填充功能正常
- 密码生成器正常
- 跨设备同步正常

**建议**

- 使用强密码保护密码管理器
- 启用双因素认证
- 定期更新密码

### 15.3 与 VPN 的协同

锁定模式与 VPN 可以协同工作：

**VPN 的作用**

- 加密网络流量
- 隐藏真实 IP 地址
- 绕过网络审查

**推荐 VPN 配置**

- 使用 Always-On VPN
- 选择可信的 VPN 提供商
- 确保 VPN 不记录日志

### 15.4 与双因素认证的协同

锁定模式增强了双因素认证的安全性：

**双因素认证类型**

| 类型 | 锁定模式下 | 安全性 |
|------|-----------|--------|
| SMS 验证码 | 正常 | 低（可被 SIM 交换攻击） |
| TOTP（Google Authenticator） | 正常 | 中 |
| 硬件安全密钥（YubiKey） | 正常（需解锁） | 高 |
| 推送通知 | 正常 | 中 |

**建议**

- 优先使用硬件安全密钥
- 避免使用 SMS 验证码
- 为所有重要账户启用双因素认证

### 15.5 与安全审计的协同

锁定模式应该配合定期的安全审计：

**审计内容**

1. **设备检查**
   - 检查已安装应用
   - 检查配置文件
   - 检查异常进程

2. **网络审计**
   - 检查网络连接
   - 检查 DNS 查询
   - 检查异常流量

3. **通信审计**
   - 检查消息记录
   - 检查通话记录
   - 检查异常联系人

4. **数据审计**
   - 检查存储的敏感数据
   - 检查云同步状态
   - 检查备份内容

## 16. 总结与建议清单

### 16.1 核心要点

1. **锁定模式是针对特定威胁的高效防护**
   - 适用于面临国家级网络攻击的高风险人群
   - 通过缩减攻击面有效防御零点击攻击
   - 不是所有用户都需要启用

2. **锁定模式有明确的功能限制**
   - 消息附件类型受限
   - 网页性能下降
   - 某些设备连接功能受限
   - 需要调整工作流程

3. **锁定模式是综合安全策略的一部分**
   - 不能替代端到端加密通信
   - 不能替代安全意识培训
   - 不能替代物理安全措施
   - 需要与其他安全措施协同使用

4. **启用锁定模式需要充分准备**
   - 准确评估威胁等级
   - 了解功能限制的影响
   - 通知关键联系人
   - 准备替代方案

### 16.4 最终建议

对于高风险人群，启用锁定模式是一个重要但非完美的安全决策。它提供了针对商业间谍软件的有效防护，但也带来了功能限制和工作流程调整。

关键决策因素：

1. **威胁是否真实存在？** 如果你面临国家级网络攻击的威胁，锁定模式是值得的。
2. **能否接受功能限制？** 如果你需要频繁处理复杂文档或使用网页应用，可能需要额外的设备或替代方案。
3. **是否有配套措施？** 锁定模式应该作为综合安全策略的一部分，而不是唯一的安全措施。

最终，安全是一个连续体，而不是一个开关。锁定模式是这个连续体上的一个重要工具，但它需要与正确的威胁评估、安全意识和技术措施结合使用，才能发挥最大效果。
