## 一、结论先行

iOS 设备存储和处理着用户最私密的数据：通信记录、位置轨迹、生物特征、财务信息和私人照片。当攻击者通过漏洞利用链获得内核级权限后，iOS 上几乎所有数据都可以被采集和回传。

核心事实：

- **数据源覆盖 13 个维度**：通信、位置、传感器、文件、应用、凭据、键盘、网络、屏幕、系统信息、健康数据、财务数据和社交关系
- **两种采集模式**：被动提取（读取已存储数据）和主动监控（实时录音、截屏、定位）
- **内核权限是关键分水岭**：获得 kernel read/write 后，iOS 的所有软件级数据保护均可被绕过
- **Secure Enclave 是最后的堡垒**：生物特征模板和私钥永不离开 Secure Enclave，无法被直接提取
- **数据采集是间谍软件的最终目的**：漏洞利用是手段，数据采集才是目标——理解采集能力才能评估真实风险
- **检测极其困难**：合法 API 调用被恶意利用时，系统层面几乎没有可观测的差异

### 2.2 iOS 数据保护类（Data Protection Classes）

iOS 使用文件级加密，每个文件根据保护级别使用不同的密钥：

```
数据保护级别与密钥关系

┌────────────────────────────┬─────────────────────────────────────┐
│ 保护级别                    │ 密钥行为                             │
├────────────────────────────┼─────────────────────────────────────┤
│ Complete Protection        │ 设备锁定后密钥即被丢弃              │
│ (NSFileProtectionComplete) │ 文件在设备锁定后不可访问            │
│                            │ 大多数用户数据使用此级别            │
├────────────────────────────┼─────────────────────────────────────┤
│ Complete Unless Open       │ 文件可以保持打开，锁定后写入        │
│ (NSFileProtectionComplete  │ 但新打开被拒绝                      │
│  UnlessOpen)               │ 用于邮件下载等场景                  │
├────────────────────────────┼─────────────────────────────────────┤
│ Complete Until First Auth  │ 首次解锁后密钥常驻内存              │
│ (NSFileProtectionComplete  │ 大多数应用数据使用此级别            │
│  UntilFirstUserAuth)       │ 重启后到首次解锁前不可访问          │
├────────────────────────────┼─────────────────────────────────────┤
│ No Protection              │ 文件仅使用 UID 密钥加密             │
│ (NSFileProtectionNone)     │ 设备锁定后仍可访问                  │
│                            │ 仅用于必要的系统文件                │
└────────────────────────────┴─────────────────────────────────────┘

关键要点：
• 设备解锁状态下，所有保护级别的密钥均可被内核访问
• 拥有内核读写权限的攻击者可以获取所有文件解密密钥
• 仅 Complete Protection 在设备锁定时提供真正保护
• 大多数间谍软件在设备解锁期间完成数据采集
```

### 3.2 数据采集权限层级

```
权限层级与数据访问能力

Level 0: 应用沙箱内
├─ 只能访问自身沙箱数据
├─ 用户明确授权的数据（通讯录、照片等）
└─ 能力极为有限

Level 1: 沙箱逃逸后
├─ 访问所有应用的容器数据
├─ 读取系统日志
├─ 访问部分系统配置
└─ 无法访问 Keychain 或受保护数据

Level 2: 内核权限（kernel read/write）
├─ 绕过所有文件级加密
├─ 访问 Keychain
├─ 绕过 TCC（透明度、同意和控制）
├─ 激活硬件传感器
├─ 拦截网络流量
└─ 完全控制系统

Level 3: 内核 + Secure Enclave 通信
├─ 理论上可请求 Secure Enclave 执行操作
├─ 但无法提取 Secure Enclave 内部数据
├─ 生物特征模板仍然不可访问
└─ 这是当前攻击的能力上限
```

### 4.2 第三方即时通讯应用

```
第三方通信应用数据采集

┌─────────────────────────────────────────────────────────────┐
│                                                               │
│  WhatsApp                                                     │
│  ├─ 数据库：ChatStorage.sqlite（应用沙箱内）                 │
│  ├─ 加密：使用 SQLCipher 加密数据库                          │
│  ├─ 密钥：存储在 Keychain 中                                 │
│  ├─ 采集路径：内核权限 → 读取 Keychain → 获取数据库密钥     │
│  │            → 解密数据库 → 读取全部聊天记录                │
│  ├─ 媒体文件：存储在应用 Documents/Media 目录                │
│  └─ 端到端加密：在设备端解密后存储，间谍软件可读明文        │
│                                                               │
│  Telegram                                                     │
│  ├─ 数据库：tgdata.db（加密）                                │
│  ├─ 秘密聊天：端到端加密，不存储在服务器                     │
│  ├─ 普通聊天：可从服务器同步，设备端有缓存                   │
│  ├─ 采集路径：读取应用内存中的解密数据                       │
│  └─ 注意：Telegram 的加密实现有自定义成分                    │
│                                                               │
│  Signal                                                       │
│  ├─ 数据库：signal.sqlite（使用 SQLCipher 加密）             │
│  ├─ 端到端加密：所有消息和通话                               │
│  ├─ 采集路径：Hook 解密后的消息处理流程                      │
│  ├─ 替代方案：读取通知内容（未加密的元数据）                 │
│  └─ 安全等级：在主流通信应用中安全性最高                      │
│                                                               │
│  微信（WeChat）                                               │
│  ├─ 数据库：WCDB（基于 SQLCipher）                           │
│  ├─ 数据：消息、联系人、朋友圈缓存                           │
│  ├─ 采集路径：读取 Keychain 中的加密密钥                     │
│  └─ 额外数据：微信支付记录、小程序使用历史                   │
│                                                               │
└─────────────────────────────────────────────────────────────┘

关键洞察：
• 端到端加密保护的是传输过程，不是设备端存储
• 消息在接收后被解密并存储在本地数据库
• 拥有内核权限的攻击者可以读取解密后的明文
• 端到端加密无法防御设备端已被入侵的情况
```

### 8.1 应用数据提取原理

```
第三方应用数据采集原理

┌─────────────────────────────────────────────────────────────┐
│                                                               │
│  iOS 应用数据存储结构：                                       │
│                                                               │
│  /var/mobile/Containers/Data/Application/<UUID>/             │

│  │  ├─ Caches/                缓存数据                       │
│  │  ├─ Preferences/           偏好设置 plist                 │
│  │  └─ Cookies/               应用 Cookie                    │
│  ├─ tmp/                临时文件                              │

│                                                               │
│  沙箱隔离：                                                   │

│  • 加密密钥通常存储在 Keychain 中                             │

### 11.2 证书固定绕过

```
证书固定（Certificate Pinning）绕过

┌─────────────────────────────────────────────────────────────┐
│                                                               │
│  证书固定的目的：                                              │
│  • 防止中间人攻击（MITM）                                     │
│  • 应用只信任特定服务器的证书或公钥                            │
│  • 即使系统信任存储被篡改也无法拦截                            │
│                                                               │
│  绕过方法（内核权限下）：                                      │
│                                                               │
│  方法一：Hook 验证函数                                         │
│  ├─ 找到应用中的证书验证回调                                   │
│  ├─ 修改返回值使其始终通过                                     │
│  ├─ 适用于使用 NSURLSession 委托验证的应用                     │
│  └─ 需要针对每个应用的验证逻辑定制                             │
│                                                               │
│  方法二：在加密前捕获数据                                      │
│  ├─ 不尝试解密 TLS 流量                                        │
│  ├─ 在数据进入加密管线前（或解密后）捕获                       │
│  ├─ Hook 应用层的读写函数                                      │
│  └─ 完全绕过 TLS 层                                            │
│                                                               │
│  方法三：修改二进制内存                                         │
│  ├─ 在运行时修改应用的证书固定逻辑                             │
│  ├─ NOP 掉验证分支或修改比较结果                               │
│  └─ 类似 Frida 的 SSL pinning bypass 但更底层                 │
│                                                               │
│  结论：                                                        │
│  • 内核权限下，证书固定无法阻止数据采集                        │
│  • 攻击者可以选择在加密前捕获明文                              │
│  • 证书固定主要防御网络层攻击，对设备端攻击无效                │
│                                                               │
└─────────────────────────────────────────────────────────────┘
```

### 13.1 数据处理管线

```
数据采集 → 处理 → 回传完整管线

┌─────────────────────────────────────────────────────────────┐
│                                                               │
│  Stage 1: 数据采集                                            │
│  ┌──────────────────────────────────────────────┐            │

### 13.2 传输隐蔽策略

```

│                                                               │
│  1. 流量伪装                                                   │
│  ├─ User-Agent 模仿合法应用                                    │

│  ├─ 请求间隔随机化（避免固定模式）                             │
│  └─ 数据量控制（避免异常大流量）                               │
│                                                               │
│  2. 域前置（Domain Fronting）                                  │
│  ├─ TLS SNI 显示合法域名（如 cdn.cloudflare.com）             │

│  ├─ 网络监控者只看到与合法 CDN 的通信                          │

│                                                               │

│  ├─ 基于种子（日期、密钥）伪随机生成域名                       │
│  ├─ 攻击者和恶意软件使用相同算法生成相同域名                   │
│  ├─ 即使一个域名被封禁，下一个域名可预测                       │
│  └─ 提供弹性的 C2 基础设施                                    │
│                                                               │
│  4. 低频传输                                                   │
│  ├─ 小批量、高频率 vs 大批量、低频率                           │
│  ├─ Pegasus 倾向低频传输（每天或每几天一次）                   │
│  ├─ 减少被流量分析发现的概率                                   │
│  └─ 代价：数据新鲜度降低                                       │
│                                                               │
│  5. 条件触发传输                                               │
│  ├─ 仅在特定条件下传输（连接特定 Wi-Fi 时）                    │
│  ├─ 仅在目标设备充电时传输                                     │
│  ├─ 仅在特定地理位置传输                                       │
│  └─ 避免在敏感环境（如政府大楼）传输                           │
│                                                               │
└─────────────────────────────────────────────────────────────┘
```

### 14.2 Secure Enclave 的边界

```
Secure Enclave：不可逾越的边界

┌─────────────────────────────────────────────────────────────┐
│                                                               │
│  Secure Enclave 存储的数据：                                   │
│  ├─ 生物特征模板（Face ID 面部数据、Touch ID 指纹数据）      │
│  │  → 这些是数学模板，不是原始图像/指纹                      │
│  │  → 永不离开 Secure Enclave                                │
│  │  → 即使在 Secure Enclave 外也不存在原始生物特征数据        │
│  │                                                             │
│  ├─ 设备 UID（唯一密钥）                                      │
│  │  → 出厂时烧录，不可读取、不可导出                          │
│  │  → 用于派生文件保护密钥                                    │
│  │                                                             │
│  ├─ Apple Pay 支付卡凭据                                      │
│  │  → 卡号和支付密钥存储在 Secure Enclave 中                  │
│  │  → 交易签名在 Secure Enclave 内完成                        │
│  │                                                             │
│  └─ 密码派生密钥                                              │
│     → 用户密码通过 Secure Enclave 内的 PBKDF2 派生            │
│     → 派生速度被硬件限制（防暴力破解）                         │
│                                                               │
│  间谍软件能做什么：                                             │
│  ✓ 请求 Secure Enclave 执行生物特征验证（如果用户刚解锁）     │
│  ✓ 利用已解锁状态访问受保护数据                                │
│  ✓ 在用户输入密码时通过键盘记录获取密码                        │
│  ✗ 直接读取 Secure Enclave 内存                                │
│  ✗ 提取生物特征模板                                            │
│  ✗ 导出 Apple Pay 卡凭据                                      │
│  ✗ 绕过密码尝试限制                                            │
│                                                               │
│  实际影响：                                                     │
│  • 间谍软件不需要生物特征模板——它已经可以访问所有其他数据     │
│  • 键盘记录可以获取密码，从而获取 Secure Enclave 保护的密钥   │
│  • 但 Secure Enclave 本身的数据（生物特征、UID）仍然安全      │
│                                                               │
└─────────────────────────────────────────────────────────────┘
```

### 16.2 锁定模式对数据采集的影响

```
锁定模式（Lockdown Mode）对数据采集的限制

┌────────────────────────────────────┬──────────────────────────┐
│ 锁定模式限制                        │ 对数据采集的影响          │
├────────────────────────────────────┼──────────────────────────┤
│ iMessage 仅允许文本和少量附件       │ 阻断 iMessage 攻击入口   │
│ 阻止有线连接                        │ 阻断物理接入攻击         │
│ 阻止描述文件安装                    │ 阻断 MDM 攻击            │
│ 阻止 WebKit JIT                    │ 减少浏览器攻击面         │
│ 图片/视频移除元数据                 │ 减少 EXIF 数据泄露       │
│ 阻止部分网络协议                    │ 增加攻击难度             │
├────────────────────────────────────┼──────────────────────────┤
│ 锁定模式不能阻止的：                │                           │
│ 已安装间谍软件的数据采集            │ 锁定模式不删除已有恶意   │
│ 零日漏洞攻击（未知漏洞）            │ 软件                     │
│ 物理接近攻击                        │ 如果已被入侵，锁定模式   │
│ iCloud 账户攻击                     │ 不阻止数据采集           │
└────────────────────────────────────┴──────────────────────────┘

结论：
• 锁定模式是预防性的，不是治疗性的
• 主要价值在于阻断攻击入口，减少被入侵概率
• 如果设备已被入侵，启用锁定模式不会停止数据采集
• 必须先清除入侵，再通过锁定模式防止重新入侵
```

│        • 发现 Pegasus 在 45 个国家的运营（Citizen Lab 报告）

│        • 引入环境录音和摄像头监控
│

│        • 首次实现零点击 VoIP 攻击入口
│        • 通过 WhatsApp 通话功能注入间谍软件
│        • 即使未接听也能成功攻击
│

## 附录 A：关键术语表

| 术语 | 定义 |
|------|------|
| C2 (Command & Control) | 命令与控制服务器，间谍软件远程接收指令和回传数据的服务器 |
| TCC (Transparency, Consent, and Control) | iOS 的隐私权限框架，控制应用对摄像头、麦克风等敏感资源的访问 |
| Keychain | iOS 的加密凭据存储服务，保存密码、密钥和证书 |
| Secure Enclave | 设备上的独立安全处理器，存储生物特征和密钥，独立于主处理器运行 |
| IOSurface | iOS 底层图形缓冲区管理框架，管理屏幕渲染的内存区域 |
| DGA (Domain Generation Algorithm) | 域名生成算法，伪随机生成 C2 域名以逃避封锁 |
| Domain Fronting | 域前置技术，通过合法 CDN 域名隐藏真实 C2 服务器 |
| MVT (Mobile Verification Toolkit) | Amnesty International 开发的 Pegasus 检测工具 |
| PAC (Pointer Authentication Code) | 指针认证码，ARM 架构的控制流完整性机制 |
| MTE (Memory Tagging Extension) | 内存标记扩展，ARM 架构的内存安全检测机制 |
| SQLCipher | 基于 SQLite 的开源加密数据库扩展 |
| WAL (Write-Ahead Logging) | SQLite 的日志模式，可能保留已删除数据的残留 |
| EXIF | 图像可交换文件格式，包含拍摄参数、GPS 等元数据 |
| JIT (Just-In-Time) | 即时编译，锁定模式限制的功能之一 |
