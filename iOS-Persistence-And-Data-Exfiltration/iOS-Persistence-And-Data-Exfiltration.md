## 1. 持久化与数据窃取概述

### 1.1 攻击链中的位置

在完整的 iOS 攻击链中，持久化与数据窃取处于漏洞利用之后的阶段：

```
攻击阶段：
1. 初始入侵（Initial Access）→ 零点击/点击攻击
2. 代码执行（Code Execution）→ 获取代码执行权限
3. 权限提升（Privilege Escalation）→ 获取内核权限
4. 持久化（Persistence）→ 确保重启后仍然存活 ← 本章重点
5. 数据收集（Collection）→ 采集目标数据 ← 本章重点
6. 数据外传（Exfiltration）→ 将数据传回 C2 ← 本章重点
```

持久化和数据窃取是间谍软件的核心价值所在。一个无法持久驻留的攻击只能获取一次性的数据访问，而一个无法窃取数据的持久化则毫无意义。两者相辅相成，构成了间谍软件的"生存"与"产出"能力。

### 1.2 持久化的定义与目标

持久化（Persistence）是指攻击者在目标设备上保持访问能力的技术和策略。在 iOS 平台上，持久化面临特殊挑战：

**iOS 的持久化挑战**

- **沙箱隔离**：每个应用运行在独立沙箱中，无法访问其他应用数据
- **代码签名**：所有可执行代码必须经过 Apple 签名
- **W^X 策略**：内存页面不能同时可写和可执行
- **安全启动链**：从 Boot ROM 到内核的完整信任链
- **文件系统加密**：数据保护机制加密用户数据
- **定期更新**：Apple 频繁发布安全更新

**攻击者的持久化目标**

1. **重启存活**：设备重启后恶意代码仍然能够执行
2. **更新存活**：iOS 更新后恶意代码仍然存活（理想情况）
3. **隐蔽性**：持久化机制不被用户或安全软件发现
4. **可靠性**：持久化机制在各种条件下稳定工作
5. **可恢复性**：即使部分组件被删除，也能恢复完整功能

### 1.3 数据窃取的定义与范围

数据窃取（Data Exfiltration）是指将目标设备上的敏感数据传输到攻击者控制的服务器的过程。完整的窃取流程包括：

```
数据窃取管线：
1. 数据发现（Discovery）→ 定位有价值的数据
2. 数据收集（Collection）→ 读取和提取数据
3. 数据暂存（Staging）→ 在设备上临时存储和压缩
4. 数据编码（Encoding）→ 加密和混淆数据
5. 数据传输（Transmission）→ 通过隐蔽通道传输
6. 数据确认（Acknowledgment）→ 确认传输完成
```

### 1.4 商业间谍软件的持久化与窃取能力

## 2. iOS 存储架构与数据保护

### 2.1 文件系统层次结构

iOS 的文件系统基于 APFS（Apple File System），具有以下层次结构：

```
文件系统层次：
├── /System（系统分区，只读，经过签名验证）
│   ├── Library（系统框架和库）
│   └── Applications（系统应用）
├── /Data（数据分区，用户可写）
│   ├── mobile（用户数据）
│   │   ├── Documents（应用文档）
│   │   ├── Library（应用库）
│   │   └── tmp（临时文件）
│   ├── private（系统私有数据）
│   └── mobile/Library/Preferences（偏好设置）
└── /private/var（可变数据）
    ├── db（系统数据库）
    ├── log（系统日志）
    └── run（运行时数据）
```

### 2.2 数据保护类（Data Protection Classes）

iOS 使用数据保护类来管理文件加密。每个文件可以关联一个保护类，决定在什么条件下可以访问：

| 保护类 | 名称 | 可访问时间 | 适用场景 |
|--------|------|-----------|---------|
| Complete | NSFileProtectionComplete | 仅设备解锁时 | 最敏感数据 |
| CompleteUnlessOpen | NSFileProtectionCompleteUnlessOpen | 解锁时或文件打开时 | 需要后台写入的文件 |
| CompleteUntilFirstAuth | NSFileProtectionCompleteUntilFirstUserAuthentication | 首次解锁后一直可访问 | 大多数应用数据 |
| None | NSFileProtectionNone | 始终可访问 | 不敏感的系统数据 |

**对攻击者的影响**

- **Complete**：设备锁定时无法访问，攻击者必须在设备解锁时窃取数据
- **CompleteUnlessOpen**：如果攻击者已打开文件，即使设备锁定也能继续写入
- **CompleteUntilFirstAuth**：设备重启后首次解锁前无法访问
- **None**：任何时候都可以访问，包括设备锁定状态

### 2.3 Keychain 与凭证存储

iOS Keychain 是存储敏感凭证的安全容器：

**Keychain 层次结构**

```
Keychain 存储：
├── kSecClassGenericPassword（通用密码）
│   ├── 应用特定密码
│   ├── API 密钥
│   └── 令牌
├── kSecClassInternetPassword（互联网密码）
│   ├── 网站登录凭证
│   └── HTTP Basic Auth
├── kSecClassCertificate（证书）
│   ├── 客户端证书
│   └── CA 证书
├── kSecClassKey（密钥）
│   ├── 私钥
│   └── 会话密钥
└── kSecClassIdentity（身份）
    └── 证书 + 私钥对
```

**Keychain 访问控制**

- 每个应用的 Keychain 项受应用标识符（App Group）限制
- 可以设置访问控制列表（ACL）
- 支持生物识别认证保护
- 与数据保护类类似，支持不同的可访问性级别

### 2.4 应用沙箱与数据隔离

每个 iOS 应用运行在独立的沙箱中：

```
应用沙箱结构：
/var/containers/Bundle/Application/<UUID>/
├── AppName.app/（应用包，只读）
├── Documents/（用户文档）
├── Library/
│   ├── Caches/（缓存）
│   ├── Preferences/（偏好设置 plist）
│   └── Application Support/（支持文件）
└── tmp/（临时文件）
```

**沙箱安全机制**

- 每个应用有唯一的 UID 和 GID
- 应用只能访问自己的沙箱目录
- 跨应用通信必须通过系统服务（如 URL Scheme、XPC）
- 共享数据通过 App Groups 或 Keychain Sharing 实现

### 2.5 对持久化和窃取的影响

iOS 的存储架构对攻击者有以下影响：

**持久化影响**

- 无法在系统分区写入（经过签名验证）
- 只能在数据分区持久化（用户可重置）
- Keychain 项在应用删除后可能保留（取决于配置）
- 文件保护类限制了锁定时访问持久化数据的能力

**窃取影响**

- 无法直接读取其他应用的数据（沙箱隔离）
- 需要内核权限绕过沙箱
- Keychain 数据需要特殊权限才能跨应用访问
- 加密数据在设备锁定时不可访问

## 3. 内核级持久化技术

### 3.1 内核扩展（KEXT）持久化

在较旧的 iOS 版本中，内核扩展（Kernel Extensions，KEXT）是一种强大的持久化机制：

**KEXT 加载机制**

```
启动流程：
Boot ROM → iBoot → Kernel → KEXT 加载
                              ↓
                        恶意 KEXT 获得内核权限
```

**持久化方式**

1. **修改 KEXT 缓存**：替换或修改 `/System/Library/Caches/com.apple.kext.caches/` 中的缓存文件
2. **注入 KEXT 依赖**：修改现有 KEXT 的 Info.plist，添加对恶意 KEXT 的依赖
3. **替换系统 KEXT**：用修改版本替换系统 KEXT

**限制**

- iOS 16+ 已完全弃用第三方 KEXT
- 系统分区经过签名验证，无法修改
- 安全启动链会检测未签名的代码

### 3.2 内核任务端口持久化

获取 `kernel_task` 端口后，攻击者可以修改内核内存实现持久化：

**技术细节**

```c
// 获取 kernel_task 端口
mach_port_t kernel_task;
task_for_pid(mach_task_self(), 0, &kernel_task);

// 修改内核内存
// 1. 修改 sysent 表（系统调用表）
// 2. 安装 rootkit 钩子
// 3. 修改进程链表隐藏恶意进程
```

**持久化方法**

1. **系统调用钩子**：修改 `sysent` 表中的函数指针，将系统调用重定向到恶意代码
2. **VFS 钩子**：修改文件系统操作函数，隐藏恶意文件
3. **进程链表操作**：从内核进程链表中移除恶意进程，使其对 `ps` 命令不可见
4. **网络栈钩子**：修改网络处理函数，实现隐蔽通信

**重启后的持久化**

内核内存修改在重启后会丢失。要实现重启后的持久化，需要：

- 修改磁盘上的内核或 KEXT（受签名验证阻止）
- 利用 boot chain 漏洞（极其稀有和珍贵）
- 在每次重启后重新利用漏洞（需要可用的漏洞利用）

### 3.3 IOKit 驱动持久化

IOKit 是 iOS 的设备驱动框架。攻击者可以利用 IOKit 实现持久化：

**IOKit 用户客户端**

IOKit 用户客户端（User Client）是内核驱动与用户态应用之间的桥梁：

```
用户态应用 → IOKit User Client → 内核驱动
```

**持久化技术**

1. **注册恶意 IOKit 服务**：在内核中注册新的 IOKit 服务
2. **修改现有驱动的匹配表**：修改驱动的匹配条件，使其加载恶意组件
3. **利用 IOKit 的自动加载机制**：当设备连接时自动加载恶意驱动

### 3.4 launchd 持久化

`launchd` 是 iOS 的初始化进程（PID 1），负责管理系统服务：

**Launch Daemons**

```
Launch Daemons 位置：
/System/Library/LaunchDaemons/（系统守护进程）
/Library/LaunchDaemons/（第三方守护进程，需越狱）
```

**持久化方法**

1. **添加 Launch Daemon plist**：在 `/Library/LaunchDaemons/` 中添加 plist 文件
2. **修改现有 Daemon**：修改系统 Daemon 的 plist，添加恶意参数
3. **利用 Watchdog 机制**：确保恶意进程在被杀死后自动重启

**限制**

- `/Library/LaunchDaemons/` 需要 root 权限写入
- 系统 Daemon 经过签名验证
- 需要越狱环境

### 3.5 内核持久化的检测

检测内核级持久化的方法：

**内存分析**

- 使用 DMA（Direct Memory Access）设备读取物理内存
- 分析内核内存中的异常修改
- 检查 sysent 表的完整性
- 验证进程链表的完整性

**行为检测**

- 监控异常的 IOKit 用户客户端注册
- 检测未签名的内核模块
- 监控系统调用的异常重定向

## 4. 用户态持久化技术

### 4.1 应用级持久化

在用户态，攻击者可以利用应用机制实现持久化：

**后台执行**

iOS 允许应用在特定条件下后台执行：

```
后台执行类型：
├── Background Fetch（后台获取）
│   └── 系统定期唤醒应用执行任务
├── Background Tasks（后台任务）
│   ├── BGAppRefreshTask（刷新任务）
│   └── BGProcessingTask（处理任务）
├── VoIP Push（VoIP 推送）
│   └── 通过 VoIP 推送唤醒应用
├── Location Updates（位置更新）
│   └── 位置变化时唤醒应用
├── Audio（音频播放）
│   └── 播放音频时保持后台运行
└── External Accessory（外部配件）
    └── 连接外部设备时保持运行
```

**滥用后台执行**

恶意应用可以滥用这些机制保持活跃：

1. **注册多个后台任务**：确保至少有一个任务在执行
2. **滥用 VoIP Push**：通过 VoIP 推送频繁唤醒
3. **伪造音频播放**：播放静音音频保持后台运行
4. **滥用位置更新**：持续请求位置更新保持活跃

### 4.2 URL Scheme 持久化

URL Scheme 允许应用通过 URL 启动：

```
自定义 URL Scheme：
myapp://action?param=value
```

**持久化技术**

1. **注册多个 URL Scheme**：确保可以通过多种方式启动
2. **与其他应用交叉调用**：建立应用间的调用链
3. **利用 Universal Links**：通过 HTTPS URL 启动应用

### 4.3 推送通知持久化

推送通知可以唤醒应用执行代码：

**静默推送（Silent Push）**

```json
{
    "aps": {
        "content-available": 1
    },
    "custom_data": "malicious_payload"
}
```

静默推送不会显示通知，但会唤醒应用执行后台代码。攻击者可以利用这一机制：

1. 定期发送静默推送唤醒应用
2. 在推送载荷中传递指令
3. 应用接收指令后执行相应操作

**限制**

- 推送必须通过 APNs（Apple Push Notification service）
- 推送载荷大小有限制
- 系统可能限制推送频率

### 4.4 Keychain 持久化

Keychain 项在应用删除后可能保留：

**Keychain 持久化机制**

```
应用删除后的 Keychain 行为：
1. 应用被删除
2. 应用沙箱被清除
3. Keychain 项保留（默认行为）
4. 重新安装应用后可以访问之前的 Keychain 项
```

**利用方式**

1. **存储恶意配置**：将 C2 地址、加密密钥存储在 Keychain 中
2. **持久化标识符**：存储设备指纹，即使重新安装也能识别
3. **恢复恶意功能**：重新安装后从 Keychain 恢复配置

**防御措施**

- 使用 `kSecAttrAccessible` 限制可访问性
- 在应用删除时主动清除 Keychain 项
- 使用 Access Control 限制访问

### 4.5 文件持久化

在应用沙箱内持久化数据：

**持久化位置**

```
持久化位置：
├── Documents/（用户文档，iCloud 备份）
├── Library/Caches/（缓存，可能被系统清理）
├── Library/Preferences/（偏好设置，plist 文件）
├── Library/Application Support/（支持文件）
└── tmp/（临时文件，可能被系统清理）
```

**隐蔽持久化技术**

1. **隐藏文件**：使用 `.` 前缀命名文件
2. **伪装文件**：将恶意数据伪装成正常文件（如图片、缓存）
3. **分散存储**：将数据分散存储在多个文件中
4. **使用系统目录**：在系统创建的目录中存储数据

### 4.6 用户态持久化的检测

检测用户态持久化的方法：

**应用行为分析**

- 监控异常的后台活动
- 检测异常的推送通知处理
- 分析网络流量模式

**文件系统分析**

- 扫描可疑的隐藏文件
- 检查异常的 plist 配置
- 分析文件访问模式

## 5. 越狱环境下的持久化

### 5.1 越狱工具持久化

越狱工具本身提供了持久化机制：

**Tethered 越狱**

- 每次重启后需要重新利用漏洞
- 不提供真正的持久化
- 适用于临时访问

**Semi-Tethered 越狱**

- 重启后设备可以正常启动
- 需要重新运行越狱应用恢复越狱环境
- 提供部分持久化

**Untethered 越狱**

- 重启后自动保持越狱状态
- 提供完整的持久化
- 极其稀有（iOS 14+ 几乎没有）

### 5.2 Cydia Substrate / Substitute

越狱环境通常使用 Substrate 或 Substitute 实现代码注入：

**工作原理**

```
应用启动 → dyld 加载 → Substrate/Substitute 注入
                              ↓
                        加载恶意动态库
                              ↓
                        钩住目标函数
```

**持久化机制**

1. **动态库注入**：在 `/Library/MobileSubstrate/DynamicLibraries/` 放置恶意 dylib
2. **过滤器配置**：创建 plist 文件指定注入目标
3. **自动加载**：每次目标应用启动时自动注入

### 5.3 越狱环境下的数据窃取

越狱环境为数据窃取提供了极大的便利：

**文件系统访问**

- 可以读取任何应用的数据
- 可以访问系统数据库
- 可以读取 Keychain 数据库

**进程注入**

- 可以向任何进程注入代码
- 可以钩住任何函数

## 6. 无文件持久化与内存驻留

### 6.1 无文件攻击概念

无文件攻击（Fileless Attack）是指不在文件系统留下持久化文件的攻击方式：

**特点**

- 不写入磁盘文件
- 仅存在于内存中
- 难以被传统安全工具检测
- 重启后通常丢失

### 6.2 iOS 内存驻留技术

在 iOS 上实现内存驻留的挑战：

**挑战**

1. **W^X 策略**：内存页面不能同时可写和可执行
2. **ASLR**：地址空间布局随机化
3. **PAC**：指针认证码防止代码注入
4. **内存压缩**：iOS 积极压缩不活跃内存
5. ** jetsam**：系统会杀死占用过多内存的进程

**技术实现**

1. **利用合法进程的内存空间**：将恶意代码注入合法进程
2. **使用 JIT 编译区域**：WebKit 的 JIT 区域允许 W+X 内存
3. **ROP/JOP 链**：使用返回导向编程避免注入代码
4. **利用系统服务的内存空间**：在系统服务进程中执行代码

### 6.3 Pegasus 的无文件实现

Pegasus 间谍软件采用了复杂的无文件技术：

**Pegasus 的内存驻留架构**

```
Pegasus 内存驻留：
├── 内核利用（Kernel Exploit）
│   └── 获取内核读写能力
├── 进程注入（Process Injection）
│   └── 将恶意代码注入 systemd 或其他系统进程
├── 内存加密（Memory Encryption）
│   └── 加密内存中的恶意代码和数据
└── 反检测（Anti-Detection）
    └── 隐藏进程、文件和网络连接
```

### 6.4 内存持久化的局限性

内存驻留的主要局限：

- **重启丢失**：设备重启后所有内存数据丢失
- **内存压力**：系统可能杀死恶意进程
- **检测困难**：需要专门的内存分析工具
- **重新利用成本**：每次重启需要重新利用漏洞

### 6.5 混合持久化策略

实际间谍软件通常采用混合策略：

```
混合持久化：
├── 内核漏洞（Kernel Exploit）
│   └── 用于获取权限和内存驻留
├── 用户态持久化（Userland Persistence）
│   └── 用于重启后的初始恢复
├── 内存驻留（Memory Resident）
│   └── 用于运行时操作
└── 文件持久化（File Persistence）
    └── 用于存储配置和收集的数据
```

## 12. 数据暂存与加密存储

### 12.1 数据暂存策略

收集的数据需要在设备上暂存，等待传输：

**暂存位置选择**

```
暂存位置：
├── 应用沙箱内
│   ├── Library/Caches/（可能被清理）
│   ├── tmp/（可能被清理）

```

**暂存策略**

- **立即传输**：收集后立即传输，不在设备上存储
- **批量传输**：积累一定量后批量传输
- **条件传输**：在特定条件下传输（如连接到 Wi-Fi 时）

### 12.2 数据加密

暂存的数据通常需要加密：

**加密算法**

- AES-256-GCM：对称加密
- RSA-2048：非对称加密（用于密钥交换）
- ChaCha20-Poly1305：替代 AES 的选择

**密钥管理**

```
密钥层次：
├── 主密钥（Master Key）
│   └── 存储在 Keychain 或内存中
├── 会话密钥（Session Key）
│   └── 用于加密当前会话的数据
└── 文件密钥（File Key）
    └── 用于加密单个文件
```

### 12.3 数据压缩

为减少传输数据量，收集的数据通常需要压缩：

**压缩算法**

- zlib：通用压缩
- LZ4：快速压缩
- bzip2：高压缩比

**压缩策略**

- 文本数据：高压缩比
- 图片数据：已经压缩，压缩比低
- 数据库：结构化数据，压缩比中等

### 12.4 数据清理

传输完成后需要清理本地数据：

**清理方式**

- **安全删除**：多次覆写后删除
- **普通删除**：直接删除文件
- **密钥销毁**：删除加密密钥，使数据不可恢复

**清理时机**

- 传输成功后立即清理
- 定期清理过期数据
- 检测到异常时紧急清理

## 13. 隐蔽数据外传通道

### 13.1 HTTP/HTTPS 通道

最常见的数据外传方式：

**HTTPS 隧道**

```
HTTPS 外传：
1. 使用标准 HTTPS 端口（443）
2. 使用合法的 TLS 证书
3. 将数据嵌入正常的 HTTP 请求/响应
4. 使用 CDN 或云服务作为中继
```

**隐蔽技术**

- **域名伪装**：使用与合法服务相似的域名
- **路径伪装**：使用看起来正常的 URL 路径
- **请求频率**：控制请求频率，避免触发告警
- **数据分片**：将大数据分成小块传输

### 13.2 DNS 隧道

使用 DNS 协议传输数据：

**DNS 隧道原理**

```
DNS 隧道：
1. 将数据编码为 DNS 查询
2. 查询恶意 DNS 服务器
3. 服务器在 DNS 响应中返回数据或确认
4. 绕过防火墙（DNS 通常不被阻止）
```

**编码方式**

- Base32 编码：将数据编码为域名
- 子域名查询：每个查询传输一小块数据
- TXT 记录：在 TXT 记录中返回数据

**限制**

- 带宽低（通常 < 100 kbps）
- 延迟高
- 可能被 DNS 监控检测

### 13.3 ICMP 隧道

使用 ICMP 协议（ping）传输数据：

**ICMP 隧道原理**

- 将数据嵌入 ICMP Echo Request/Reply
- 绕过基于端口的防火墙
- 通常不被网络监控关注

**限制**

- 带宽极低
- 容易被专门的 ICMP 监控检测
- 在移动网络上不稳定

### 13.4 云服务中继

使用合法云服务作为中继：

**中继服务**

```
云服务中继：
├── 云存储（Dropbox、Google Drive）
│   └── 将数据上传到云存储
├── 社交平台（Twitter、Telegram）
│   └── 通过私信或帖子传输数据
├── 代码托管（GitHub、GitLab）
│   └── 将数据隐藏在代码提交中
└── 消息服务（Firebase、Pusher）
    └── 使用推送服务传输指令和数据
```

**优势**

- 流量看起来正常
- 使用合法的 TLS 证书
- 难以与服务正常流量区分

### 13.5 蓝牙与近场通信

在特定场景下使用近场通信：

**蓝牙数据外传**

- 当设备靠近攻击者的接收器时传输
- 用于物理接近场景
- 带宽有限但隐蔽性高

**NFC 数据外传**

- 需要极近的物理距离
- 带宽极低
- 用于特定场景的数据传输

### 13.6 数据外传的检测

检测数据外传的方法：

**网络监控**

- 异常的数据上传量
- 异常的 DNS 查询模式
- 异常的 ICMP 流量
- 连接到可疑的 IP 地址

**设备监控**

- 异常的电池消耗
- 异常的数据使用
- 异常的 CPU 使用
- 异常的网络活动模式

## 14. C2 通信协议与基础设施

### 14.1 C2 通信架构

典型的 C2（Command and Control）通信架构：

```
C2 架构：
┌─────────────┐
│  间谍软件    │ ← 设备上的恶意代码
└──────┬──────┘
       │ 加密通信
       ↓
┌─────────────┐
│  中继服务器   │ ← 可能有多层中继
└──────┬──────┘
       │
       ↓
┌─────────────┐
│  C2 服务器    │ ← 攻击者控制的核心服务器
└─────────────┘
```

### 14.2 通信协议设计

C2 通信协议的设计考虑：

**协议层次**

```
协议栈：
├── 传输层（TCP/UDP/HTTP/DNS）
├── 加密层（TLS/自定义加密）
├── 认证层（设备认证、密钥交换）
├── 命令层（指令编码、响应格式）
└── 数据层（数据分片、压缩、编码）
```

**指令类型**

- **心跳**：定期报告设备在线状态
- **配置更新**：更新间谍软件配置
- **数据收集**：触发数据收集任务
- **数据上传**：指令上传收集的数据
- **模块加载**：下载和执行新模块
- **自毁**：删除间谍软件

### 14.3 域名生成算法（DGA）

使用 DGA 生成随机域名用于 C2 通信：

**DGA 原理**

```
DGA 流程：
1. 使用种子（日期、设备 ID 等）生成随机域名
2. 尝试连接生成的域名
3. 攻击者注册其中一个域名
4. 建立 C2 通信
```

**优势**

- 难以阻止所有可能的域名
- 即使部分域名被封禁，仍有备用
- 可以基于时间同步生成域名

### 14.4 域前置（Domain Fronting）

使用域前置隐藏真实的 C2 服务器：

**域前置原理**

```
域前置：
1. 客户端连接 CDN（如 Cloudflare）
2. TLS SNI 显示合法域名
3. HTTP Host 头显示真实 C2 域名
4. CDN 将请求转发到真实 C2
```

**优势**

- 网络监控看到的是合法 CDN 流量
- 难以区分正常流量和 C2 流量
- 利用 CDN 的合法性和可靠性

### 14.5 快速翻转（Fast Flux）

使用快速翻转技术保护 C2 基础设施：

**快速翻转原理**

- C2 域名频繁更换 IP 地址
- 使用僵尸网络作为代理
- 即使部分 IP 被封禁，仍有备用

### 14.6 C2 基础设施的保护

攻击者保护 C2 基础设施的措施：

**多层防护**

- 使用 CDN 隐藏真实服务器
- 使用代理链隐藏来源
- 使用加密货币支付基础设施费用
- 定期更换基础设施

**冗余设计**

- 多个备用 C2 服务器
- 多个通信通道
- 多个中继节点

## 15. 持久化与窃取的检测方法

### 15.1 设备行为分析

通过设备行为检测异常：

**电池分析**

- 异常的电池消耗模式
- 设备锁定时仍然消耗电量
- 特定应用或进程的异常耗电

**网络分析**

- 异常的数据使用量
- 异常的网络连接模式
- 连接到可疑的 IP 或域名
- 异常的 DNS 查询模式

**性能分析**

- 设备响应变慢
- 应用启动变慢
- 异常的 CPU 使用
- 设备异常发热

### 15.2 文件系统分析

通过分析文件系统检测持久化：

**可疑文件检测**

- 扫描隐藏文件
- 检查异常的 plist 配置
- 分析文件修改时间
- 检测异常的文件权限

**数据库分析**

- 检查系统数据库的异常修改
- 分析应用数据库的异常访问
- 检测异常的 Keychain 项

### 15.3 内存分析

通过内存分析检测无文件攻击：

**内存取证**

- 使用 DMA 设备获取物理内存
- 分析进程内存中的异常代码
- 检测异常的内存映射
- 分析内核内存的完整性

**运行时分析**

- 监控进程创建和销毁
- 检测异常的内存分配
- 分析系统调用的异常模式

### 15.4 网络流量分析

通过网络流量分析检测数据窃取：

**流量特征**

- 异常的数据上传量
- 异常的协议使用
- 异常的加密模式
- 异常的通信时间模式

**深度包检测**

- 分析 TLS 握手的异常
- 检测 DNS 隧道
- 检测 ICMP 隧道
- 分析 HTTP 请求的异常

### 15.5 专业检测工具

**Citizen Lab 工具**
