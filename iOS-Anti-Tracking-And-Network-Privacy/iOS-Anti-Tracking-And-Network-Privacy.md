## 1. 网络追踪的威胁全景

### 1.1 网络追踪的定义与分类

网络追踪（Web Tracking）是指通过技术手段收集、关联和分析用户在互联网上的行为数据，以建立用户画像的过程。

**追踪类型分类**

| 类型 | 描述 | 技术 | 隐私影响 |
|------|------|------|---------|
| 第一方追踪 | 网站自身追踪用户 | Cookie、登录状态 | 低 |
| 第三方追踪 | 外部实体追踪用户 | 第三方 Cookie、像素 | 高 |
| 跨站追踪 | 跨多个网站追踪 | 超级 Cookie、指纹 | 极高 |
| 应用追踪 | 移动应用追踪 | IDFA、设备指纹 | 高 |
| 网络层追踪 | ISP/运营商追踪 | DPI、DNS 日志 | 中高 |

### 1.2 追踪技术演进

追踪技术经历了多次演进，以应对隐私保护措施：

**第一代：Cookie 追踪（1990s-2010s）**

- 第三方 Cookie 是最主要的追踪方式
- 广告商通过 Cookie 跨站追踪用户
- 简单有效，但容易被用户清除

**第二代：Flash Cookie / Local Storage（2010s）**

- 使用 Flash LSO 或 HTML5 Local Storage
- 更持久，不易被用户清除
- 与 Cookie 同步实现"复活"

**第三代：浏览器指纹（2010s-2020s）**

- 收集浏览器和设备的各种特征
- 无需存储任何数据
- 包括 Canvas、WebGL、字体、屏幕分辨率等

**第四代：超级 Cookie / Evercookie（2010s）**

- 同时在多个存储位置写入标识符
- 清除一个位置后从其他位置恢复
- 极难完全清除

**第五代：服务器端追踪（2020s+）**

- 不依赖客户端存储
- 通过服务器端关联用户行为
- 使用 IP 地址、会话特征等

**第六代：AI 驱动追踪（2020s+）**

- 使用机器学习分析用户行为
- 无需明确的标识符
- 通过行为模式识别用户

### 1.3 追踪者的动机

不同追踪者的动机分析：

**广告商**

- 建立用户兴趣画像
- 投放定向广告
- 衡量广告效果
- 优化广告投放策略

**数据经纪人**

- 收集和整合用户数据
- 出售用户画像
- 提供数据分析服务
- 年收入数十亿美元

**社交平台**

- 了解用户兴趣和行为
- 优化内容推荐
- 提高用户参与度
- 增加广告收入

**恶意追踪者**

- 窃取个人信息
- 进行身份盗窃
- 实施精准诈骗
- 进行 stalking

### 1.4 iOS 平台的追踪威胁

iOS 设备面临的特定追踪威胁：

**应用内追踪**

- 应用收集设备信息
- 应用追踪网络活动
- 应用共享数据给第三方

**浏览器追踪**

- Safari 中的第三方追踪
- WebKit 指纹
- 跨站请求追踪

**网络层追踪**

- ISP 记录浏览历史
- Wi-Fi 运营商追踪
- 蜂窝网络位置追踪

**广告标识符追踪**

- IDFA（广告标识符）
- 设备指纹
- 概率性标识符

## 2. iOS 反追踪技术架构

### 2.1 Apple 的隐私理念

Apple 将隐私视为基本人权，其反追踪技术架构体现了这一理念：

**核心原则**

- **最小化数据收集**：只收集必要的信息
- **本地处理优先**：尽可能在设备上处理数据
- **透明度**：让用户知道数据如何被使用
- **用户控制**：让用户控制自己的数据
- **安全默认**：隐私保护默认启用

### 2.2 反追踪技术层次

iOS 的反追踪技术分为多个层次：

```
反追踪技术层次：

│          浏览器层防护                      │
│  （ITP、指纹防护、Cookie 控制）            │
├─────────────────────────────────────────┤
│          网络层隐私                        │
│  （iCloud 专用中继、加密 DNS、VPN）        │
├─────────────────────────────────────────┤
│          系统层保护                        │
│  （MAC 地址随机化、私有 Wi-Fi 地址）       │
├─────────────────────────────────────────┤
│          硬件层安全                        │
│  （Secure Enclave、安全启动）              │

```

## 3. 智能追踪防护（ITP）

### 3.1 ITP 概述

智能追踪防护（Intelligent Tracking Prevention，ITP）是 Safari 浏览器的核心反追踪技术，从 iOS 11 开始引入。

**ITP 的目标**

- 防止第三方 Cookie 追踪
- 限制存储追踪
- 防止浏览器指纹
- 阻断跨站追踪

### 3.2 ITP 的工作原理

ITP 通过多种机制实现追踪防护：

**第三方 Cookie 阻止**

```
ITP Cookie 策略：
├── 第一方 Cookie：允许
├── 第三方 Cookie：默认阻止
├── 例外：用户交互过的站点
└── 存储限制：7 天（无交互）
```

**存储分区**

- 每个站点的存储被分区
- 防止跨站存储访问
- Cookie、LocalStorage、IndexedDB 都被分区

**追踪器检测**

- 使用机器学习识别追踪器
- 基于已知追踪器列表
- 基于行为分析

### 3.3 ITP 的演进

ITP 经历了多次重要更新：

**ITP 1.0（iOS 11）**

- 阻止第三方 Cookie
- 限制存储追踪
- 基本指纹防护

**ITP 2.0（iOS 12）**

- 更严格的存储限制
- 防止 CNAME 伪装
- 增强指纹防护

**ITP 2.1（iOS 13）**

- 7 天存储限制
- 防止追踪器复活
- 更严格的分区

**ITP 2.3（iOS 14）**

- 对首次访问的站点限制为 1 天
- 更严格的 CNAME 检测
- 防止私有 bounce 追踪

**ITP 3.0+（iOS 15+）**

- 持续增强
- 更智能的追踪器检测
- 更好的用户体验平衡

### 3.4 ITP 的影响

ITP 对网络生态的影响：

**对追踪者的影响**

- 第三方 Cookie 追踪大幅减少
- 存储追踪受到限制
- 需要开发新的追踪技术
- 推动向服务器端追踪转移

**对广告商的影响**

- 定向广告效果下降
- 需要寻找替代方案
- 推动隐私友好型广告技术
- 促进上下文广告发展

**对用户的影响**

- 隐私保护显著提升
- 广告相关性降低
- 某些网站功能可能受影响
- 更好的浏览体验

### 3.5 ITP 的局限性

ITP 的已知局限性：

**技术局限**

- 无法防御所有追踪技术
- 服务器端追踪难以检测
- 需要持续更新以应对新技术
- 可能影响某些合法功能

**兼容性挑战**

- 某些网站功能可能受影响
- 需要网站适配 ITP
- 可能增加开发复杂度

**绕过技术**

- CNAME 伪装（ITP 已修复）
- 私有 bounce 追踪（ITP 已修复）
- 服务器端追踪（仍在对抗）

## 4. iCloud 专用中继

### 4.1 iCloud 专用中继概述

iCloud 专用中继（iCloud Private Relay）是 Apple 在 iOS 15 引入的网络隐私服务，属于 iCloud+ 订阅的一部分。

**核心功能**

- 隐藏用户的真实 IP 地址
- 加密 DNS 查询
- 通过两个中继路由流量
- 防止 ISP 和网站追踪

### 4.2 技术架构

iCloud 专用中继使用两跳架构：

```
iCloud 专用中继架构：
┌─────────────┐
│  iOS 设备    │
└──────┬──────┘
       │ 加密连接
       ↓
┌─────────────┐
│  入口中继    │ ← Apple 运营
│  （第一个）   │
│  - 分配匿名 IP │
│  - 知道源 IP   │
│  - 不知道目标  │
└──────┬──────┘
       │ 加密连接
       ↓
┌─────────────┐
│  出口中继    │ ← 第三方运营
│  （第二个）   │
│  - 知道目标   │
│  - 不知道源 IP │
│  - 分配临时 IP │
└──────┬──────┘
       │
       ↓
┌─────────────┐
│  目标网站    │
└─────────────┘
```

**关键特性**

- Apple 知道用户的源 IP，但不知道访问的目标
- 第三方运营出口中继，知道目标，但不知道源 IP
- 没有任何单一实体知道完整的浏览信息
- 使用 HTTPS 加密所有连接

### 4.3 配置选项

iCloud 专用中继提供多种配置选项：

**网络隐私级别**

```
隐私级别：
├── 维护 IP 地址大致位置
│   └── 网站可以看到国家和区域
│   └── 平衡隐私和兼容性
└── 限制 IP 地址位置
    └── 网站只能看到国家
    └── 更高隐私，可能影响服务
```

**应用范围**

- Safari 浏览
- 应用网络流量（可选）
- DNS 查询

### 4.4 隐私效果

iCloud 专用中继的隐私效果：

**防御的威胁**

- ✅ ISP 浏览追踪
- ✅ Wi-Fi 运营商追踪
- ✅ 网站 IP 追踪
- ✅ DNS 追踪
- ✅ 网络层关联

**不能防御的威胁**

- ❌ 登录账户追踪
- ❌ 浏览器指纹
- ❌ 应用内追踪
- ❌ 设备指纹

### 4.5 限制与注意事项

iCloud 专用中继的限制：

**订阅要求**

- 需要 iCloud+ 订阅（50GB 或以上）
- 每月额外费用

**兼容性**

- 某些网站可能检测到代理
- 某些服务可能无法使用
- 企业网络可能阻止

**性能影响**

- 可能增加延迟
- 可能影响速度
- 某些地区性能较差

**地区限制**

- 在某些国家/地区不可用
- 受当地法规限制

## 5. 加密 DNS 与隐私解析

### 5.1 DNS 追踪威胁

传统 DNS 查询面临的隐私威胁：

**明文 DNS 的问题**

- DNS 查询以明文传输
- ISP 可以记录所有查询
- Wi-Fi 运营商可以监控
- 中间人可以篡改响应

**DNS 追踪的影响**

- 暴露用户访问的网站
- 可以构建浏览历史
- 可以用于内容过滤
- 可以用于广告定向

### 5.2 加密 DNS 协议

iOS 支持多种加密 DNS 协议：

**DNS over HTTPS（DoH）**

```
DoH 特点：
├── 通过 HTTPS 加密 DNS 查询
├── 使用标准 HTTPS 端口（443）
├── 难以被网络层阻止
└── 与 Web 流量混合
```

**DNS over TLS（DoT）**

```
DoT 特点：
├── 通过 TLS 加密 DNS 查询
├── 使用专用端口（853）
├── 易于识别和阻止
└── 性能略优于 DoH
```

### 5.3 iOS 加密 DNS 配置

在 iOS 上配置加密 DNS：

**方法一：描述文件**

```
配置步骤：
1. 从 DNS 提供商下载描述文件
2. 安装描述文件
3. 在设置中信任描述文件
4. 配置 DNS 服务器
```

**方法二：手动配置**

```
配置步骤：
1. 设置 → Wi-Fi
2. 点击当前网络的详情
3. 配置 DNS → 手动
4. 输入加密 DNS 服务器地址
```

**方法三：应用配置**

- 使用 DNS 提供商的应用
- 应用自动配置加密 DNS
- 一键启用

### 5.4 推荐的加密 DNS 提供商

注重隐私的加密 DNS 提供商：

**Cloudflare DNS**

- 地址：1.1.1.1 / 1.0.0.1
- 协议：DoH、DoT
- 隐私政策：不记录查询
- 速度：快

**Quad9**

- 地址：9.9.9.9 / 149.112.112.112
- 协议：DoH、DoT
- 隐私政策：不记录查询
- 安全：阻止恶意域名

**NextDNS**

- 自定义配置
- 协议：DoH、DoT
- 隐私政策：可配置
- 功能：广告阻止、家长控制

**AdGuard DNS**

- 地址：94.140.14.14 / 94.140.15.15
- 协议：DoH、DoT
- 隐私政策：有限记录
- 功能：广告阻止

### 5.5 加密 DNS 的局限性

加密 DNS 的局限性：

**不能隐藏的信息**

- 目标 IP 地址仍然可见
- SNI（Server Name Indication）可能泄露域名
- 流量模式仍然可分析

**需要配合的技术**

- 需要配合 VPN 或代理
- 需要配合 HTTPS
- 需要配合 ECH（Encrypted Client Hello）

## 6. 网络指纹防护

### 6.1 浏览器指纹概念

浏览器指纹（Browser Fingerprint）是指通过收集浏览器和设备的各种特征，创建唯一标识符的技术。

**指纹特征类型**

```
指纹特征：
├── 用户代理字符串
├── 屏幕分辨率和颜色深度
├── 时区和语言
├── 已安装字体
├── Canvas 指纹
├── WebGL 指纹
├── 音频指纹
├── 插件列表
├── 触摸支持
├── 硬件并发
├── 设备内存
└── 电池状态
```

### 6.2 iOS 指纹防护

iOS 和 Safari 的指纹防护措施：

**Safari 指纹防护**

- 限制可访问的浏览器特征
- 标准化用户代理字符串
- 限制字体访问
- Canvas 指纹随机化
- WebGL 指纹限制

**WebKit 防护**

- 减少暴露的 API
- 限制高精度计时器
- 限制硬件访问
- 标准化行为

### 6.3 指纹防护的效果

iOS 指纹防护的效果评估：

**防护效果**

- 显著减少指纹熵
- 使设备更难被唯一识别
- 增加追踪成本

**局限性**

- 无法完全消除指纹
- 某些特征仍然可用
- 需要持续更新

### 6.4 高级指纹技术

高级指纹技术的防御：

**Canvas 指纹**

- Safari 对 Canvas 渲染添加噪声
- 每次会话使用不同的噪声
- 防止跨会话追踪

**WebGL 指纹**

- 限制 WebGL 信息访问
- 标准化渲染器信息
- 防止 GPU 指纹

**音频指纹**

- 限制 AudioContext 访问
- 标准化音频处理
- 防止音频指纹

## 7. Cookie 与存储隐私

### 7.1 Cookie 隐私问题

Cookie 面临的隐私问题：

**第三方 Cookie**

- 被广泛用于跨站追踪
- 用户难以控制
- 隐私影响大

**超级 Cookie**

- 使用多个存储位置
- 难以完全清除
- 持久性追踪

### 7.2 iOS Cookie 管理

iOS 对 Cookie 的管理：

**Safari Cookie 设置**

```
设置路径：
设置 → Safari → 阻止 Cookie

选项：
├── 始终阻止
├── 仅阻止第三方
├── 允许当前网站
└── 始终允许
```

**存储清理**

- 自动清理不活跃站点的存储
- 用户可以手动清理
- 私密浏览模式不保存

### 7.3 Local Storage 与 IndexedDB

本地存储的隐私管理：

**存储分区**

- 每个站点的存储被分区
- 防止跨站存储访问
- ITP 自动管理

**存储限制**

- 7 天无交互后清理
- 追踪器存储更短
- 用户可以手动管理

## 8. VPN 策略与选择

### 8.1 VPN 在隐私保护中的角色

VPN 在网络隐私保护中的作用：

**VPN 的功能**

- 加密所有网络流量
- 隐藏真实 IP 地址
- 绕过地理限制
- 防止 ISP 追踪

**VPN 的局限**

- 需要信任 VPN 提供商
- 可能影响性能
- 某些服务阻止 VPN
- 不能防御所有追踪

### 8.2 iOS VPN 配置

iOS 上的 VPN 配置方式：

**内置 VPN 协议**

- IKEv2
- IPSec
- L2TP（不推荐）

**现代 VPN 协议**

- WireGuard（通过应用）
- OpenVPN（通过应用）

**VPN 配置方法**

- 手动配置
- 描述文件配置
- VPN 应用

### 8.3 隐私友好的 VPN 选择

选择隐私友好 VPN 的考虑因素：

**关键标准**

- 无日志政策
- 独立审计
- 司法管辖区
- 支付方式
- 透明度报告

**推荐 VPN**

- Mullvad
- ProtonVPN
- IVPN
- Windscribe

### 8.4 VPN 与 iCloud 专用中继

VPN 与 iCloud 专用中继的配合：

**配合策略**

- iCloud 专用中继处理 Safari
- VPN 处理其他应用流量
- 可以互补使用

**注意事项**

- 可能影响性能
- 需要正确配置
- 某些组合可能冲突

## 9. Wi-Fi 隐私与安全

### 9.1 Wi-Fi 追踪威胁

Wi-Fi 网络面临的隐私威胁：

**MAC 地址追踪**

- 设备 MAC 地址唯一
- 可用于追踪设备位置
- 可用于关联用户行为

**Wi-Fi 网络追踪**

- 运营商可以监控流量
- 可以记录浏览历史
- 可以注入广告

### 9.2 私有 Wi-Fi 地址

iOS 的私有 Wi-Fi 地址功能：

**功能说明**

- 为每个 Wi-Fi 网络生成唯一 MAC 地址
- 防止跨网络追踪
- 默认启用

**配置选项**

```
设置路径：
设置 → Wi-Fi → 网络详情 → 私有 Wi-Fi 地址

选项：
├── 固定（默认）：每个网络使用固定私有地址
├── 轮换：定期更换地址
└── 关闭：使用真实 MAC 地址
```

### 9.3 Wi-Fi 安全最佳实践

Wi-Fi 隐私安全的最佳实践：

**公共 Wi-Fi**

- 使用 VPN
- 避免敏感操作
- 使用 HTTPS
- 不自动连接

**家庭 Wi-Fi**

- 使用强密码
- 启用 WPA3
- 定期更换密码
- 监控连接设备

## 11. 应用网络隐私控制

### 11.1 应用网络权限

iOS 对应用网络权限的控制：

**本地网络权限**

- 应用访问本地网络需要权限
- 用户可以控制
- 防止本地网络扫描

**后台网络权限**

- 限制后台网络活动
- 用户可以查看
- 可以禁用

### 11.2 应用追踪透明度

应用追踪透明度（ATT）的详细说明：

**ATT 机制**

- 应用请求追踪权限
- 用户可以允许或拒绝
- 拒绝后 IDFA 返回零值

**ATT 效果**

- 大幅减少应用追踪
- 90%+ 用户拒绝追踪
- 推动隐私友好型广告
